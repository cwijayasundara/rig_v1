## 1. Commands/skills, order in the journey, hand-offs

### Takeaway
rig ships 17 skills (no `commands/` dir; every command is a `skills/<name>/SKILL.md`), 2 agents and 5 hook events. The core ladder is init -> (chart, optional) -> start -> plan -> {approve} -> build -> test -> pr -> merge, with `build -> test -> pr` auto-chained in one turn after the one human approval. Every skill ends with an explicit `Next:` line (a stated design principle).

### Cited Findings

**Naming.** Plugin mode: `/rig:<name>`. After `init --full` the harness is vendored into the repo and each skill answers only to its folder name, `/rig-<name>` (`skills/init/SKILL.md` Both step 3; `scripts/core.ts:203` `skillRef` returns `/rig-x` if vendored or `.claude/skills/rig-start/SKILL.md` exists, else `/rig:x`). Init must "write them as `/rig-start`, `/rig-approve`" in all output. Plugin manifest: name `rig`, version 0.7.0 (`.claude-plugin/plugin.json`). Install is `claude --plugin-dir /abs/path/to/rig_v1` or project-scope marketplace install; "Never register at user scope" (README Install; CLAUDE.md "Plugin scope").

**Skill inventory (17), grouped by journey position.** (frontmatter in `skills/<n>/SKILL.md`)

Onboarding / maintenance of the install
- `/rig:init [--quick|--defaults] [greenfield "<stack and goal>"]` (model: sonnet). One-time. Runs `sdlc.ts init` (refuses and relays if `.rig/bin` is older than plugin), `sdlc.ts superpowers` check (asks to install superpowers; never stops init for it), then Brownfield (3 parallel Haiku `Explore` scouts: stack+module map / real build-test-lint commands / conventions+gotchas; verify fast test cmd; write CLAUDE.md <=120 lines with `## Review` and `# Compact instructions`; existing CLAUDE.md gets a proposed diff, never overwrite; ends with `wiki init` which only proposes `.rig/wiki.json`) or Greenfield (ask up to 3 questions: stack/deploy/test framework; scaffold walking skeleton + 1 smoke test + lint; CLAUDE.md with `## Planned (from the PRD)`; skip wiki). Then Both: (1) `init --stack` writes `.rig/sensors.json` from `templates/stacks/*.json` (node, python, go, rust, java-maven, java-gradle, dotnet, angular per README), `sync` writes guides block into CLAUDE.md; (2) `baseline` runs turn-cadence sensors once, failing ids -> `knownRed`; (3) `init --full` vendors harness (`.rig/bin`, `.claude/skills/rig-*`, `.claude/agents/rig-*`, merges `templates/settings.json`, wires git hooks), `--workflows` writes `.github/workflows/rig-check.yml` + `REVIEW.md` only with a remote; (4) verify workflows/remote, optionally `init --protect` (required checks) and `init --enforce` (`risk.enforce`); (5) README rig block between `<!-- rig:begin -->`/`<!-- rig:end -->` markers; commit step. Ends with a `Next:`: `/rig:chart 0 @docs/prd/sprint-0/prd.md` (greenfield or any repo with a PRD) or `/rig:start "<first task>"` (no PRD). Modes: `--quick` (all recommended answers, adds workflows if `origin`), `--defaults` (unattended, no workflows, prints `--protect --dry`). Sources: `skills/init/SKILL.md`, README "Install".
- `/rig:upgrade [--force]` (model: sonnet). `sdlc.ts upgrade --json` (read-only plan: from/to, replace/keep/add/delete counts, migrations, proposed sensors, `held` sensors e.g. Semgrep `sast`); one AskUserQuestion batch for conflicts (keep mine / take new / show diff / write `.rig-new`); multi-select for proposed sensors; `upgrade --apply --decide '<json>'` creates `chore/rig-upgrade-<to>`, vendors, runs numbered migrations (`scripts/migrations.ts`), `sync` + `baseline`, one commit, stops; never pushes; ends `Next: review and merge the branch; nothing was pushed`. Backed by `.rig/bin/MANIFEST.json` (version + hash per file) and 3-way merge (docs/HISTORY.md "2026-10-26-rig-upgrade" digest). Must be run from the newer plugin (README atlas). CI workflow `rig-check.yml` is the team's file: upgrade writes `rig-check.yml.rig-new`.

Outer loop (sprint, optional)
- `/rig:chart [N | path | --convert-only]` (architect role). 8 steps (`skills/chart/SKILL.md`): (1) resolve sprint/PRD (`chart next --json`; PRD accepted in any format from any path); require `.rig/sensors.json`; ensure a base commit (asks to commit init output); copy PRD unchanged to `source.md` (+ `attachments/`); `prd check` -> convert to rig PRD format (`templates/prd-format.md`: AC-n.m, DR-n, NFR-n) with `conversion.md` mapping every source sentence word-for-word; **Coverage** (`coverage.md` from `source.md` only vs `templates/prd-topics.md`; `prd coverage`; open topics block approval; `prd gaps` writes `client-gaps.md` to send back to the client); **Gap pass** (technology, NFRs, ambiguities, contradictions with existing tests; one AskUserQuestion batch of <=4, plus a second design batch of <=4); conversion check + `rig:evaluator` conversion review -> `conversion-review.md`; **ledger** `prd ledger` -> `requirements.md` (generated); (2) Design: runs `superpowers:brainstorming` in ONE batch (not a conversation) writing `docs/superpowers/specs/<date>-sprint-<N>-design.md` with `## Intents` and `## Design`; then `rig:architect` (Sonnet, foreground) writes `intents/<slug>.md`, `implementation-plan.md`, `architecture.md`, `brief.md`, ADRs under `.rig/product/adr/`; edge-case checklist `templates/edge-cases.md`; sprint 0 always has a `walking-skeleton` intent; (3) `chart check <N>`, <=1 fix round; (4) QA: a Sonnet general-purpose agent writes `testplan/plan.md`, `cases.md`, `data/`; `chart check --cases`; (5) `rig:evaluator` (Opus) reviews bundle -> `chart-review.md`, <=1 fix round + confirm pass; (6) `chart plan` generates `plan.md` (waves, owners, graphs); (7) commit on `rig/chart-<N>`; (8) final message: open coverage gaps, "Proposed by the agent" table (`prd proposed`), intents, graph, allocation, review verdict, `Next: review the branch ... then a person runs /rig:approve chart-<N>`. Chart has 4 `AskUserQuestion` stops max in design (memory: "4 stops"). Reads `.rig/wiki/index.md` as recon when present.
- `/rig:testplan <N>` (QA lead). Standalone redo of chart step 4 after PRD/intent change (`skills/testplan/SKILL.md`: "`/rig:chart <N>` already runs this as its step 4").
- `sdlc.ts ready` / `queue next` / `chart next` (no skill; CLI only): list intents whose `depends:` have shipped; `queue next` names the next ready intent depending on autonomy rung.

Inner loop (one change)
- `/rig:start "<task>" [--full] | --from-diff ["<what for>"] | <slug> | .rig/product/sprints/sprint-<N>/intents/<slug>.md`. Opens with `start-brief` (injected via `!` command: warnings, ready intents list). With empty args it lists ready intents as a numbered list and stops. Creates `.rig/changes/<slug>/` via `S new` with type feature|bugfix|refactor|chore; charted intent carries B-numbers and a generated `requirements.md` (PRD words for this change; never edited). Conversation: `settled: yes` (charted and answered) -> ask nothing; `settled: no (<reasons>)` -> ask only those; free text/`--from-diff` -> full `superpowers:brainstorming` grill, one batch <=4; uses wiki as recon if `.rig/wiki/index.md` exists. Writes `intent.md` (<=15 lines) and `spec.md` (`## Behaviours` B1.., `## Blast radius`, `## Out of scope`, `## Open questions`). `S weight` -> light (default, plan <=30 lines, no writing-plans) or full (always-human paths, `## Access` action, `--full`). Then continues to `/rig:plan` in the same turn unless open questions remain. `--from-diff` captures vibe-coded/explored work as a change (red-proof runs new tests on the base without captured code).
- `/rig:plan [slug]`. Writes `plan.md`: `## Files` (inside blast radius), `## Interfaces`, `## Phases` (full only), `## Tests` (one per B-number), `## Contracts`, `## Verification`, `## Decisions`, `## Open questions`. Runs `queue --check` (file held by another in-flight plan = stop), `approve <slug> --check`, edits contract files BEFORE approval (approval freezes them), launches `rig:evaluator` (Opus, change-plan mode) only when weight is full or a contract is listed. Ends `Next: /rig:approve <slug> (a person), then /rig:build <slug>`.
- `/rig:approve <slug | chart-N>` (human only: `disable-model-invocation: true`; runs `SDLC_HUMAN=1 sdlc.ts approve`). Bare form: `approve --ask` returns ASK lines; skill offers "Approve and build" / "Only approve" / "Cancel". On "Approve and build" it invokes `/rig:build <slug>` via Skill tool. Writes `approval.json` with hashes of spec.md, plan.md and frozen contract files (chart: PRD, intents, architecture, ADRs, test plan, contracts); goes stale on any change; `approve chart-N` commits `chore: approve chart-N` (CHANGELOG, shop_app cart-core fixes) and refuses with open coverage topics/blocking findings.
- `/rig:build [slug]`. Requires status `build` (stops at `approve`). Branch `sdlc/<slug>` if on trunk. Per behaviour: write test naming B-number and AC id (`test_ac_1_2_...`), `S run --expect-fail -- "<cmd>"` must fail, write code, `S run -- "<cmd>"` must pass. Test-plan case data loaded unchanged from `testplan/data/`. Touch only plan `## Files`. Optional <=1 Sonnet agent per independent file group. Continues to `/rig:test` in same turn.
- `/rig:test [slug]`. `S verify <slug>` runs every commit/ci sensor, contract commands (validate first), traceability (each B-number named by a test), red-proof (feature/bugfix new tests fail on base; refactor passes) -> `verify.json`. Stops and asks person if the same finding fails twice (may `/rig:waive`). Continues to `/rig:pr`.
- `/rig:pr [slug]`. Risk-tiered review of the DELTA before any PR: `S risk --pre-review`: tier 0 no agent (writes `review.md` with `reviewer: none`), tier 1 Opus clean-context code reviewer (`templates/review-brief.md`), tier 2 adds Opus security agent. Triage rules (dismissals need cited reason; never dismiss security/contract/design/unmapped), one fix wave, Opus confirm pass, `amendments.md`, `S verify` again, `S wiki sync --max-usd 1` (warn-only), `pr-outline.md`, `S pr --message` (refuses without approval + fresh passing `verify.json`; commits code + review.md; push; PR or local-only). Posts review via `gh pr comment`. Ends `Next: a person reviews and merges the PR`; runs `S queue next` and prints `Queue: <slug> is ready` at rung >=1. Then CI `rig-check` re-judges with the base branch checker (README "What fires when").

Human-only, off the main path
- `/rig:waive <sensor> <file|*> <reason> [--days N] | chart-<N> <finding#> <reason>` (human only). Appends `.rig/waivers.jsonl`.
- `/rig:autonomy [set <0|1|2|3> --why "<text>"]` (human only). Rung 0 person starts each intent; 1 session opens next intent's brainstorm; 2 unattended after approve (merge manual); 3 trusted tier-0 PRs pass with no person while `risk.enforce` on and revert breaker holds (README). `set 3` refuses until `risk.enforce` and `humanApproval.trusted` set. Stored in `.rig/autonomy.json`.

Alongside (not on the main ladder)
- `/rig:wiki init|build|status|verify|refresh` (plus `sync` used by `/rig:pr`). `init` has Sonnet propose `.rig/wiki.json` (<=30 pages) for a person to edit; `build --max-usd N` writes `.rig/wiki/<page>.md`, `index.md`, `state.json`; every line one sentence ending in a `[path#symbol]` citation, script-validated, clean-context reviewer drops unsupported claims; `status` free, warn-only; never edit pages by hand.
- `/rig:learn [--max-usd N]` (model: sonnet). `learn mine` (recurring review findings/waivers in >=2 changes, `--transcripts` mines the person's typed corrections locally), `learn reverts` (reverted changes -> candidate review cases in `.rig/learn/review-cases/`), proposes delta edits (ADD/MERGE/RETIRE/PROMOTE/LAYER) in `.rig/learn/proposal.md`; never edits lessons or rules; a person applies in a PR. `.rig/lessons.md` <=30 active lines.
- `/rig:rule "<what recurs>"`. Needs >=2 real occurrences; drafts a regex rule for `.rig/rules.json` (block/warn) or one line for CLAUDE.md `## Things Claude gets wrong`.
- `/rig:arch [propose|check]`. Proposes a `rig-layers` block in `.rig/product/architecture.md` from observed imports; person judges edges; human runs `SDLC_HUMAN=1 sdlc.ts arch approve` (writes `.rig/gen/` analyser config and baselines existing violations).
- `/rig:app [<name>]`. Writes a journey driver under `.rig/verify/<app>/` (`app.json`, driver, `features/*.md`), person approves with `SDLC_HUMAN=1 sdlc.ts app approve <app>`; verify/PR/CI then run it. Reads `.rig/wiki` when present.

**Agents (2).** `agents/architect.md`: Sonnet, effort high, maxTurns 30, tools Read/Grep/Glob/LSP/Write/Edit, writes only under `.rig/product/` and `docs/contracts`, never source code; replies in <=15 lines. `agents/evaluator.md`: Opus, effort high, read-only Bash; modes: chart, conversion check, change plan, test plan. A change's diff is reviewed by anonymous `general-purpose` Opus agents launched from `/rig:pr`, not by a named agent.

**Hooks ("mods").** `hooks/hooks.json`: `UserPromptSubmit` -> `sdlc.ts hook prompt-submit` (snapshots turn baseline; records `/rig:approve <target>` from the person's own prompt so `SDLC_HUMAN` is set only by a person); `Stop` -> `hook stop` (runs sensors on the turn's diff, blocks max 2 times, then writes `.rig/unresolved.json`); `SessionStart` (startup|resume|clear|compact) -> `hook session-start` (injects active change, its next command, policy for this model, guides; wires git hooks); `PostToolUse` Write|Edit|MultiEdit -> `hook post-edit` (secrets / plans-with-code rejection, per-file sensors, guide injection); `PostToolUse`/`PreToolUse` Agent -> `agent-done`/`agent-launch`; `PostModelSwitch` -> `model-switch` (records which model did what, selects policy). `"modules": ["./dashboard.tsx"]` is the journey dashboard mod. No hook on Bash. Git hooks pre-commit / pre-push (`scripts/githooks.ts`) and CI `rig-check` complete the layers. Memory note (MEMORY.md "Mods, not hooks"): the owner calls hooks.json + hooks.ts "mods".

**State carried between stages (all files; README "Where everything lives").** `.rig/changes/<slug>/` {intent.md, spec.md, plan.md, approval.json, evidence/runs.jsonl, verify.json, pr.md, review.md, amendments.md, plan-review.md, requirements.md}; `.rig/state/active` (active change); `.rig/product/` {brief.md, architecture.md, adr/, backlog.md, sprints/sprint-N/{prd.md, source.md, conversion.md, conversion-review.md, coverage.md, client-gaps.md, requirements.md, intents/, implementation-plan.md, plan.md, testplan/, chart-review.md, approval.json, carried/, attachments/}}; `.rig/sensors.json` (registry, policy, `knownRed`, contracts, gates), `.rig/rules.json`, `.rig/guides/`, `.rig/autonomy.json`, `.rig/waivers.jsonl`, `.rig/wiki.json` + `.rig/wiki/`, `.rig/lessons.md` + `.rig/learn/`, `.rig/bin/` + `.claude/` (vendored harness). Status is "derived from which files exist" (README; DESIGN.md principle 2; GOAL "Not goals": no state machine). Machine-local gitignored: `.gate`, `.baseline`, `unresolved.json`, `gates.jsonl`.

**Approval gates (exhaustive).** Two main human gates: `/rig:approve chart-<N>` and `/rig:approve <slug>`. Others: `/rig:waive`, `/rig:autonomy set`, `arch approve`, `app approve` (all `SDLC_HUMAN=1`, person-only); merge itself; a PR that adds/edits an `approval.json` or waiver rows needs GitHub approval from someone other than its author (CI), or the opt-in lead override (`humanApproval.selfApprovers`, label `rig-lead-override`, GitHub Environment). `risk.enforce` requires one other-person approval on every PR. CLAUDE.md for this repo: "A model never approves."

**Role mapping.** README "Who does what": Product owner/BA writes `brief.md` + `prd.md`; Architect runs `/rig:chart`; QA lead reviews test plan / `/rig:testplan`; Engineer runs start..pr; Reviewer/code owner approves approval.json PRs; Platform team owns managed settings, CODEOWNERS, production gate.

## 3. Where the journey is incoherent, hidden or hard to discover

### Takeaway
There IS a documented ladder in the README (diagram + atlas + paths A-D) and a runtime "next command" mechanism (session-start hook, `Next:` lines, dashboard mod), but there is no `/rig:status` or `/rig:help` skill; the README is ~500 lines and mixes ladder, governance, eval and dev content; naming differs between plugin and standalone modes; and several documents are stale or contradict each other.

### Cited Findings
- No status/next/help skill exists: the 17 skill dirs are app, approve, arch, autonomy, build, chart, init, learn, plan, pr, rule, start, test, testplan, upgrade, waive, wiki (`ls skills`). "Where am I / what next" is `node .rig/bin/sdlc.ts status` (CLI, JSON via `--journey --json`), injected by the `session-start` hook (README "What fires when"), and drawn by the dashboard mod `hooks/dashboard.tsx` (band with sprint rail, change rail, next command, spend; "Read-only: every step and command comes from `sdlc.ts status --journey --json`"). GOAL Open list: "Journey dashboard: does the mod API still exist in the current Claude Code, and can a status line alone show the journey and next command?" — i.e. the primary "where am I" UI depends on an unverified API (`docs/GOAL.md` line 155; mod imports `claude-code` atoms in `hooks/dashboard.tsx` line 5). `/rig:start` with empty args does show ready intents (`skills/start/SKILL.md`).

## 4. Brownfield-oriented versus greenfield parts

### Takeaway
Brownfield understanding is concentrated in `/rig:init` (scouts, CLAUDE.md, real commands, baseline), `/rig:wiki` (cited code map), `/rig:arch` (existing import layers, baselined violations), `/rig:app` (journeys over the running app), `--from-diff` capture, the `refactor` type and the architect's "read the code first" rule. Greenfield is only a scaffolding path in init plus sprint 0's mandatory `walking-skeleton` intent. Everything else (approval, sensors, PR) is mode-agnostic.

### Cited Findings
- Brownfield init: 3 parallel Haiku `Explore` scouts (module map; exact build/test/lint commands incl. fast targeted test; conventions/gotchas), verifies the fast test command by running it, writes CLAUDE.md <=120 lines, never overwrites an existing one (writes `CLAUDE.md.proposed` under `--defaults`), only replaces the README block between markers — `skills/init/SKILL.md` Brownfield 1-4, `--defaults`.
- Baseline of existing debt: `sdlc.ts baseline` runs each turn-cadence sensor once and records failing ids as `knownRed` so "the gate never blocks on debt it did not create"; a finding already red on the base is treated as known-red — `skills/init/SKILL.md` Both step 2; `README.md` lines 91, 269, 379.
- Code wiki (Devin DeepWiki-inspired per GOAL Sources): `wiki init` proposes <=30 pages, `build --max-usd`, citations `[path#symbol]` validated by script, clean-context reviewer prunes unsupported claims, hash-based staleness warn-only; `/rig:pr` runs `wiki sync` after every change; start/chart brainstorm use it as recon — `skills/wiki/SKILL.md`, `skills/start/SKILL.md` step 2, `skills/chart/SKILL.md` step 2, `skills/pr/SKILL.md` step 5. Journey logic treats a repo as brownfield iff `.rig/wiki.json` exists and its `origin` is not `sync`: `repoKind()` in `scripts/journey.ts` (comment: "Brownfield is the repo init indexed (`wiki init` writes wiki.json)"); `show = ['outer']` for brownfield and `['outer','inner']` for greenfield. So brownfield status detection is a side-effect of wiki.json, not of a declared mode.
