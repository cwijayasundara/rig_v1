## Notes on this run (harness readiness 2.2)

- Sonnet (claude-sonnet-5-5), 30 calls (5 changes x 2 arms x 3 runs), no failures, $1.01. The two arms got the same brief, diff, intent, spec, plan, touched files and existing tests, with no tools; the same-context arm differed only by opening as the engineer who built the change and by holding that builder's notes.
- **Result: no difference.** Both arms caught all four seeded defects in 12 of 12 runs each, raised no finding on the clean change in 3 of 3 runs each, and differed by 0.25 extra findings per defect run (1.00 against 1.25), which is inside the noise at n=3.
- **What this does not show.** It does not show the clean-context review is better; it shows that on defects this plain, Sonnet is not talked out of them by the builder's rationale. The four defects each break a stated B-number in a few lines of diff, so they are easy for any reviewer. The proposal's claim (Cognition: a diff-only reviewer finds more) concerns subtler defects and a long build transcript, neither of which this tests. Matching is by file and a loose pattern, so an extra finding may be a real issue, not a false one; no one read them. No tools were given, so a reviewer that runs the tests is not measured. n=3, one model.
- **What would test it:** harder defects (a failure that needs two files read together, a missing edge case, an old test pinned to the old behaviour), a real long builder transcript instead of a short rationale, and reading the extra findings to separate real issues from false ones.
- The clean-context design stays: it costs about the same, loses nothing here, and removes the builder from the loop. This eval just gives no evidence that it gains anything yet.
