# PRD: Shopping Cart API, sprint 0

<!-- Written for a coding agent: every decision needed to build without asking is below. Where a value was chosen by the author rather than the client, the Decisions section says so. -->

## Context and problem

A small HTTP service holds one shopping cart in memory. A client (a script, `curl`, or a future front end) needs to add items to it, fetch one item by id, and list every item.
This is a greenfield service: nothing exists yet and nothing else depends on it.

## Goals and success metrics

- Every criterion below passes under `uv run pytest -q`.
- `ruff check .` and `mypy .` report no errors.
- The three scenarios work by hand against a running server with `curl`.

## Non-goals

- No authentication, users or multiple carts: there is one cart per running process.
- No update or delete of items (delete arrives in sprint 1).
- No checkout, payment, tax, discounts, totals or currency handling.
- No persistence: a restart empties the cart.
- No UI, no pagination, no filtering or sorting options on the list.

## Users and scenarios

One persona: a developer or script calling the API.

- S1. POST `/items` with `{"name": "Coffee beans", "price": 8.5, "quantity": 2}`. Response 201 with the item and a new `id`.
- S2. GET `/items/<that id>`. Response 200 with the same item.
- S3. GET `/items` after two adds. Response 200 with both items, oldest first. On a fresh server it returns `[]`.

## Functional requirements

### FR-1: Add an item

Need: put a new item in the cart.
Priority: must

- AC-1.1: WHEN POST /items receives `{"name": "Coffee beans", "price": 8.5, "quantity": 2}` THE SYSTEM SHALL respond 201 with `{"id": "<id>", "name": "Coffee beans", "price": 8.5, "quantity": 2}` and store the item
- AC-1.2: WHEN two items are added THE SYSTEM SHALL give them different ids, even when name, price and quantity are identical, and keep both items
- AC-1.3: WHEN name is missing, not a string, empty, or only whitespace THE SYSTEM SHALL respond 400 `validation_error` and store nothing
- AC-1.4: WHEN price is missing, not a JSON number (a string such as "8.50" or a boolean counts as not a number), negative, or has more than 2 decimal places THE SYSTEM SHALL respond 400 `validation_error` and store nothing
- AC-1.5: WHEN quantity is missing, not a JSON integer (8.0, "2" and true are rejected), or below 1 THE SYSTEM SHALL respond 400 `validation_error` and store nothing
- AC-1.6: WHEN the body is not valid JSON or is not a JSON object THE SYSTEM SHALL respond 400 `validation_error` and store nothing
- AC-1.7: WHEN the body contains a field other than name, price and quantity (including `id`) THE SYSTEM SHALL ignore that field and generate the id itself
- AC-1.8: WHEN a request is rejected THE SYSTEM SHALL return a message that names the offending field

### FR-2: View an item by id

Need: fetch one item.
Priority: must

- AC-2.1: Given an item was added, when GET /items/{id} is called with its id, then the response is 200 with exactly the item returned at creation
- AC-2.2: WHEN GET /items/{id} is called with an id that is not in the cart THE SYSTEM SHALL respond 404 `not_found` with the message "Item <id> not found"

### FR-3: View all items

Need: list the cart.
Priority: must

- AC-3.1: WHEN GET /items is called on an empty cart THE SYSTEM SHALL respond 200 with `[]`
- AC-3.2: WHEN GET /items is called THE SYSTEM SHALL respond 200 with every item in the order they were added, oldest first
- AC-3.3: WHEN GET /items is called THE SYSTEM SHALL not change the cart

## Data rules

- DR-1: An item has exactly four fields: `id` (string), `name` (string), `price` (number), `quantity` (integer).
- DR-2: `id` is a UUID version 4 in canonical lowercase hyphenated form, generated by the server, unique within the process, and never reused.
- DR-3: `name` is stored exactly as sent apart from leading and trailing whitespace, which is trimmed; the trimmed value is non-empty.
- DR-4: `price` is held as `decimal.Decimal` with at most 2 decimal places, at least 0 (0 is allowed), and is returned in JSON as a number (8.5, not "8.50").
- DR-5: `quantity` is an integer of at least 1, with no upper limit.

## Non-functional requirements

| ID | Category | Requirement | Target | Verified by |

| NFR-1 | correctness | concurrent adds in the same process never lose an item or reuse an id | 100 concurrent adds leave exactly 100 items with 100 distinct ids | unit |

## Examples

Add (AC-1.1):

```
POST /items
{"name": "Coffee beans", "price": 8.5, "quantity": 2}

201 Created
{"id": "3f2b8c1e-6d1a-4c53-9a7e-0b5d2f6c8e11", "name": "Coffee beans", "price": 8.5, "quantity": 2}
```

Rejected add (AC-1.5):

```
POST /items
{"name": "Tea", "price": 3, "quantity": 0}

400 Bad Request
{"error": "validation_error", "message": "quantity must be an integer of at least 1"}
```

Not found (AC-2.2):

```
GET /items/does-not-exist

404 Not Found
{"error": "not_found", "message": "Item does-not-exist not found"}
```

### Error shape

Every error response is JSON `{"error": "<code>", "message": "<human text>"}` with the status given in the criterion. Codes: `validation_error` (400), `not_found` (404).
FastAPI's default 422 body is replaced by this shape through an exception handler, so a request that fails validation returns 400, never 422.

## Boundaries

- Always: run `uv run pytest -q`, `uv run ruff check .` and `uv run mypy .` before finishing; keep business logic in `store.py`, not in route functions.
- Ask first: adding a runtime dependency beyond fastapi and uvicorn, or changing a response shape.
- Never: use floats to hold or compare money; add persistence; add endpoints not listed here.

## Integrations and constraints

- Language and runtime: Python 3.12.
- Web framework: FastAPI (latest 0.x release at project creation), served by uvicorn; JSON over HTTP, no HTML.
- Tooling: uv for the environment and dependencies (`pyproject.toml` + `uv.lock`), pytest for tests with FastAPI's `TestClient` (needs `httpx`), ruff for lint, mypy for types.
- Layout: `src/cart/` with `main.py` (FastAPI app, routes only), `models.py` (pydantic request and response models), `store.py` (the in-memory cart), `errors.py`; tests in `tests/` (`test_api.py`, `test_store.py`).
- Entry point: `uv run uvicorn cart.main:app --port 8000`; tests: `uv run pytest -q`.
- Storage: in-memory only; the cart is empty at every process start. No database, no files.
- No authentication, no CORS configuration, no environment variables, no Docker, no CI configuration.
- Nothing external is called; the build needs no credentials, accounts or network beyond installing packages.

## Decisions

- 2026-11-23: Python 3.12 + FastAPI, uv, pytest, ruff, mypy — the original PRD said "if REST" and left the language open; chosen so the build needs no questions (proposed, author's choice, not yet confirmed by the client).
- 2026-11-23: ids are UUID4 strings; list order is insertion order; 400 (not 422) for all validation errors; error body shape as above (proposed).
- 2026-11-23: price is a JSON number with at most 2 decimals, held as Decimal (proposed; the original PRD said only "number >= 0").
- 2026-11-23: unknown extra fields are ignored rather than rejected (proposed).
