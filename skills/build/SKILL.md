# Build a change

`S` means `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts`.

1. Run `S status --json`; the change (`$0` or the active one) must be at `build`; at `approve`, stop: a person approves first.
2. If HEAD is the trunk, run `git checkout -b sdlc/<slug>`.
3. Read `.rig/changes/<slug>/requirements.md` when it exists: the PRD's own words for this change; never edit it; a test asserts each row's numbers and limits as written. Tests and code come from two contexts. First run `S models <slug>`: it prints the `build`, `evaluate`, `security` and `fallback` models for this change's weight.
   - (a) Test writer: launch one `general-purpose` agent on the `build` model, in the foreground, with a brief of at most 40 lines: spec.md's behaviours, requirements.md, plan.md's interfaces, the contract files, the test command, and these rules, ending with: `End your answer with one line: status: DONE, status: DONE_WITH_CONCERNS <the concern>, or status: BLOCKED <why>.` For each behaviour in order, write the test that names its B-number and each acceptance criterion it proves: `test_ac_1_2_...`, or the id (`AC-1.2`) in the test title; `pr` refuses a change whose intent cites an AC that no test names. A test for a case whose Data column names a file (`data/blank-sku.json`) loads it from the sprint's `.rig/product/sprints/sprint-<N>/testplan/data/`, unchanged, never a copy or inline dict. It reads interfaces only, never the bodies of source files the plan changes, and sees each test fail with `S run --expect-fail -- "<test command>"`.
   - When `intent-map.md` exists (frozen at approval; never edit it), the brief adds: write the formal checker its `## Formal command` names and the empirical tests, each scenario's test runnable with `S run`. The checker is frozen with the tests: `tests-freeze` takes its path (the first script file under `## Formal command`) from the map even outside the test paths; a checker not found that way must live under the test paths. The test writer does not run `S intent-record`, plant mutants or adjudicate: that is (c), after the code passes.
   - (b) Run `S tests-freeze <slug>`: it hashes the test files, their support files and fixtures, snapshots and runner config in the diff into `tests.freeze.jsonl`, and commits them (`test(<slug>): freeze tests from the test writer`) so the hand-off commit holds the tests alone; it refuses to freeze nothing when spec.md has B-numbered behaviours. The freeze is enforced once committed: from here a change to a frozen file blocks locally and in CI, however it is written, and code committed before the hand-off blocks at ship.
   - (c) Implementer (this context; for `weight: light`, one `general-purpose` agent on the `build` model, in the foreground, with a brief of at most 60 lines: the behaviours, the plan's files and interfaces, the test command, ending with `End your answer with one line: status: DONE, status: DONE_WITH_CONCERNS <the concern>, or status: BLOCKED <why>.` - the main thread does not write the code; when `S verify` fails twice on that build, launch one implementer on the `fallback` model with the failure output): write code until `S run -- "<test command>"` passes, never editing a frozen test. A wrong test goes back to (a) with the reason, then run `S tests-freeze <slug> --why "<reason>"`; a frozen file leaves the set only with `--drop <file>` (repeatable); each re-freeze and drop is listed for the reviewer and the PR needs a person. A `mutation-diff` failure goes back to the test writer (step a) with the survivor list, then `S tests-freeze <slug> --why "<reason>"`; the implementer never edits a frozen test to kill a mutant. When the code passes and `intent-map.md` exists: run each scenario with `S intent-record <slug> <E-id> -- "<test command>"`, which writes `status`, `command` and `commit` itself; never write them. Plant each clause's bug in a scratch copy, never the branch, and list it in the checker's JSON line. A surviving planted bug is fixed (tighten the clause, which needs a re-approval) or, when the mutant is not a bug, ruled on by a person with `S intent-adjudicate <slug> <mutant-id> non-bug --clause <C-id> --by <name> -- "<reason>"`; never write `adjudications.json` yourself.
   When `intent.md` has a `from-diff:` line the code already exists: the test writer writes each behaviour's test and sees it pass with `S run -- "<test command>"`, no `--expect-fail` step; `/rig:test`'s red-proof then runs the new tests on the base, without the captured code, where they must fail. A test passing there proves nothing: rewrite the test, never the base.
   Touch only the files plan.md lists; for another, add it under `## Files` with the reason under `## Decisions`, then the person reapproves (`gates.plan: false`: `S plan-check <slug> --commit` commits the in-scope amendment on its own). A change to approved scope, contracts or acceptance criteria goes to the chart: stop, keep the branch, record the path or criterion and why in the blocked status.
   A listed test pinning behaviour this change alters is updated to the new expectation (never an assertion removed or loosened); run the whole suite before `/rig:test`.
   When plan.md has `## Phases`, finish and verify one phase before the next and tick it (`- [x]`); a resumed build starts at the first unticked phase.
4. For an operation that can raise, check each step after the commit point (rename, replace, commit, send): it must not report failure once the change is in place, or the code says why.
5. The hooks run the sensors after each edit and each turn. Fix what they report; when a finding survives your fix, write in one sentence the premise it rested on and check it before the next. Never weaken a test, sensor or contract file.
6. For a large plan, run one foreground `general-purpose` agent on the `build` model per independent group of files, each with a brief of at most 60 lines: the behaviours, the files and the test command.
7. Hidden acceptance cases run in `/rig:test`; a failure names a case id and its requirement: fix the code against it. The hook hiding them is a guardrail; CI, which runs every case from the base branch, is the check.
8. An agent that ends `status: BLOCKED`, or a launch denied for the launch budget, gives `S pr <slug> --draft "<why>" --message "<type(scope): summary>"` and no retry.
9. Tests use the stand-in the architecture's `## Integrations` row names; a test needing a live service is marked and skips without credentials.
10. When every behaviour has a passing test, continue with `/rig:test <slug>` this turn.
