# Start a change

!`node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts start-brief 2>&1 || true`

If the brief above has a `WARNING` line, show it to the person first in one line, then carry on. If `$ARGUMENTS` is empty, do not run `ready` yourself: show the brief's ready intents as a numbered list, say a number, a slug or a new request starts one, and stop.

`S` means `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts`. Run each command as its own Bash call (no `cd`, pipes, redirects, `&&` or variables).

1. **Which change.** If `$ARGUMENTS` names an existing `.rig/changes/<slug>/`, run `S activate <slug>` and continue at the first missing file below. Otherwise pick a kebab-case slug of at most five words and a type: `feature` (new behaviour), `bugfix` (wrong behaviour), `refactor` (same behaviour, new structure) or `chore` (no behaviour change). If `$ARGUMENTS` contains `--full`, strip it from the request and add `--full` to the `S new` call below. If it contains `--from-diff`, the person is capturing work already done (explored or vibe-coded): strip it, run `S new <slug> --from-diff --type <type> --title "<one line>"` (pick slug and type from the request and the files it lists), show the person any `WARNING` line, and read each captured file before step 2; `spec.md` starts with those files as its blast radius. Run `S new <slug> --type <type> --title "<one line>"`. A bare `<slug>` that names a charted intent (the dashboard prints `/rig:start <slug>`) with no `.rig/changes/<slug>/` is that charted intent: Glob `.rig/product/sprints/*/intents/<slug>.md` and use the file found as the argument below. A `.rig/product/sprints/sprint-<N>/intents/<slug>.md` argument is a charted intent: use its slug and run `S new <slug> --source <file> --title "<its heading>"`; if it refuses, print the reason and stop. The change then starts with the intent's behaviours in `spec.md` (same B-numbers): keep them, add only behaviours that cite a requirement from the intent's `prd:` list, and carry the intent's text into intent.md. When `S new` reports `requirements.md`, read it: it is the PRD's own words for this change, copied by rig; never edit it, and no behaviour may contradict it.
2. **Conversation.** A charted intent was already questioned at chart, so read the `settled:` line that `S new` or `S activate` printed. `settled: yes`: ask nothing, skip the rest of this step and go to step 3; only when the change touches a UI, first ask the design-system question below. `settled: no (<reasons>)`: the batch below holds only those reasons (an open question, a carried `C<n>`, a behaviour with no requirement, missing non-goals, a boundary with no contract); ignore the list of foreseeable questions in it. No `settled:` line (a free-text request or `--from-diff`): the full conversation below. Invoke `superpowers:brainstorming` on the intent. Its opening material is the intent file (or the request), the sprint design doc named by the `design:` line of `.rig/product/architecture.md` when present (`design: none`, the template default, counts as none), and `.rig/product/brief.md` (stay inside its non-goals). One added line: the design doc is frozen, so this conversation settles only this change's behaviours, edge cases and blast radius, and a point that needs the design doc changed goes under `## Open questions`, not into the doc. Skip the skill's size step. The skill does its own recon; When `.rig/wiki/index.md` exists, hand the brainstorm the code wiki as recon: it reads the pages that name the files in play, trusts a page only through its `[path#symbol]` citations, and runs `S wiki status` first, treating a stale page as a hint to read the cited code, never as fact. For a `--from-diff` change the grill works from the captured code: for each thing the code does, ask whether the person wants it, and record only confirmed behaviours; code nobody wants goes under `## Out of scope` with a note that the build removes it, and its files stay in `## Blast radius` (plan.md lists them, so the build may remove them). Let it run its conversation, then continue below. If the brief carries the superpowers `WARNING`, skip the `Skill` call: the batch rule below is then the whole conversation. The conversation is one batch: collect every question you can foresee (edge cases, failure behaviour, what is out of scope, who is hurt if it is wrong, each `C<n>` in `.rig/product/sprints/sprint-<N>/carried/<slug>.md`, when that file exists) and ask them in one `AskUserQuestion` batch of at most 4, then write spec.md; ask a second batch only for a question an answer created. Each carried `C<n>` ends in spec.md, as a behaviour or under `## Out of scope` with the person's reason (approval checks this). Do not end it while `## Open questions` has an item without a person's answer or a default the person accepted. Three more rules for it: when the change touches a UI, ask what design system, theme and component patterns the app uses before proposing screens; only a person closes an open question (you may recommend an answer, never record one as decided); when documents disagree the latest wins: this conversation, then `spec.md`, then the design doc, then the intent.
3. **intent.md and spec.md.** Fill `## Intent` of `.rig/changes/<slug>/intent.md` in at most 15 lines: the problem, who has it, what done looks like. Then write `.rig/changes/<slug>/spec.md`:
   - `## Behaviours`: one line per observable behaviour, numbered `B1`, `B2`, … (a charted intent's B-numbers kept). A refactor lists the behaviours it must keep; a chore may write `none`. Every behaviour gets a test that names its number.
   - `## Blast radius`: the files and directories this change may touch, one per line; `plan.md` stays inside it and `S approve` refuses a plan that does not.
   - `## Out of scope`.
   - `## Open questions`: `none` once each is answered, or its default recorded under `## Decisions`.
4. Run `S weight <slug>` and tell the person the weight and its reasons in one line (`light` is the default; `full` for an always-human path, an `## Access` action or `--full`). To plan it full instead, they ask for full and you add `weight: full` to the `intent.md` frontmatter. Then continue with `/rig:plan <slug>` in this turn. Stop here instead only while `## Open questions` has an item a person must answer: list it and end with `Next: answer the open questions, then /rig:plan <slug>`.
