# Initialise this repo
**Subagents:** run them in the foreground (never `run_in_background`) and wait; never end your turn while one is running. Every agent of one step goes in one message. Run each command as its own Bash call (no `cd`, pipes, redirects, `&&`, variables or heredocs); read files with Read; one-line commit messages — compound commands are denied in unattended runs and stall the install.

Run `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts init --onboarding` first (`--onboarding`: what init writes over the next turns, a scaffold or CI workflows, opens no ad-hoc change until the preflight step). **Model check:** if this session's main model is an Opus model, say so in one line before any other step (init is orchestration and file writes, so Sonnet does it at a fraction of the cost; `templates/settings.json` pins Sonnet only for later sessions) and offer to continue after `/model sonnet`. Never stop on it; with `--defaults` or `--quick` just note it in the final table.
## `--defaults` mode
When the arguments contain `--defaults`, the person has pre-approved every recommended answer below, so ask no AskUserQuestion at all. Use these answers:
- Greenfield: stack, deployment target and test framework come from the quoted goal; anything it leaves out takes the recommended default (deployment: local only).
- **Sensors:** write `.rig/sensors.json` with `fast` and `full` as maps from a name to a command, never a bare string: `{"fast": {"test": "<fast test command>"}, "full": {"test": "<full test command>", "lint": "<lint command>"}}`; then `gates` (default: design for M, spec, plan and design for L), `value.rate` $100/h and no `consumers`. Then run `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts init --stack`: it declares `levels` from the shipped stack template, with `acceptance` and `api` set to the unit command. Do not write `levels` or `quality` yourself: the settings ask rule on `.rig/sensors.json` makes a person confirm any declared command a model adds, and an unattended run cannot answer. Then run `sdlc.ts baseline` as in Both step 2. Say that `quality` and a real acceptance or api command need the person's yes (re-run `/rig:init` without `--defaults`).
- Run `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts init --full`: it vendors the standalone harness, wires the git hooks and merges `templates/settings.json` into `.claude/settings.json`.
- Skip: `--workflows` (`.github/workflows/rig-check.yml` and `REVIEW.md`): it needs a remote, so it stays an explicit yes.
- Existing `CLAUDE.md` still gets a proposed diff, never an overwrite: write the diff to `CLAUDE.md.proposed` and say so.
End with a table of every answer taken and every item skipped, and how to do each skipped one (re-run `/rig:init` without `--defaults`).
## `--quick` mode
The fast lane for a person at the keyboard, so the "skip in unattended or cloud runs" notes of Both step 3 do not apply: everything in `--defaults` (same answers, no AskUserQuestion at all) except its Skip bullet, which this mode replaces with one item, taken as a yes without asking: **Workflows:** add `--workflows` to `init --full` only when `git remote get-url origin` succeeds; with no remote, skip and say so. The permission prompts of the settings ask rule (not a question you ask) still have the person confirm the `.rig/sensors.json` and `.claude/settings.json` edits. A remote not named `origin` gets no workflows: say so in the table. `quality` and a real acceptance or api command stay a re-run without a flag, as under `--defaults`. End with the same table as `--defaults`.

## Brownfield (source code exists)
1. Launch three `rig:scout` agents **in one message** so they run in parallel:
   - (a) stack, entry points and a module map;
   - (b) the exact build, test, lint and type-check commands, including a fast targeted test command and how to make output quiet;
   - (c) conventions, gotchas, environment setup and things that must never be done.
2. Verify the fast test command by running it once with quiet output.
3. Write `CLAUDE.md` in **at most 120 lines**. Sections:
   - a first line under the title, verbatim: `sdlc routes all work in this repo: start with /rig:start; use superpowers skills only when an sdlc skill names one.` Skills are `/rig:x` in every install mode (a standalone install names its vendored skills `rig:x` too), so never write `/rig-start`.
   - What this is (3 lines)
   - Map (directories, one line each)
   - Commands
   - Conventions
   - Gotchas
   - `# Compact instructions`: keep the active sdlc change, failing tests and file paths; drop exploration output.

   If a `CLAUDE.md` already exists, propose edits as a diff and do not overwrite it.

## Greenfield
1. Ask up to three questions with AskUserQuestion: stack, deployment target, and test framework (recommend defaults).
2. Scaffold the smallest walking skeleton that builds, plus one passing smoke test, a lint config, and a `Makefile` or package scripts with `test`, `test-fast` and `lint` targets. For Node the `lint` script is `node --check src/index.js`; never write scaffold helper files under `.rig/` (that is the vendored harness, and writing there asks the person). For Node, the test script is `node --test` with no directory argument: Node 24 reads `test/` as a module path and fails with `MODULE_NOT_FOUND` before any test runs, which also stops the red-proof gate on the base commit.
3. Write `CLAUDE.md` as above, then `git init` if needed.

## Both
1. **Sensors.** Detect the stack from scout (a) and propose `levels` and `quality` from `${CLAUDE_PLUGIN_ROOT}/templates/stacks.json`, adjusted to what scout (b) found (the real test command, an existing linter config). Also `fast` and `full` as maps from a name to a command (`{"fast": {"test": "<fast test command>"}, "full": {"test": "<full test command>", "lint": "<lint command>"}}`; a bare string is a config error and blocks every ship), plus `contracts` globs, `limits`, and any e2e, smoke or bench command found (say what each proves). Leave `tests` out unless test files live outside the defaults (`**/test/**`, `**/tests/**`, `**/*.test.*`, `**/*.spec.*`, ...): a `tests` list replaces the defaults, so a narrower one is flagged as weakening the harness; if you add one, keep every default in it. Show one `sensors.json` and write `.rig/sensors.json` on a yes (with `--defaults`, follow that mode: `init --stack` declares the levels). Tier L requires `levels` for unit, integration (when the plan spans modules), acceptance and api (endpoint changes): declare all four, with the real command for each (acceptance and api usually an e2e or HTTP test script); an undeclared required level blocks verification. A category the person declines is left out and reads `unmeasured`. Run each proposed `quality` command once before writing: one that cannot produce its count (a missing tool, `npm audit` with no lockfile) is left out and named in the summary with why and how to enable it (install the tool, `npm i --package-lock-only`), never written as a sensor that fails on every change. Ask with AskUserQuestion (unless `--defaults`): per-tier gates (default: design for M, spec, plan and design for L), the value rate (default $100/h), and whether other repos consume this one's API (each becomes a `consumers` entry: `name`, `path`, `repo`, `test`).
2. **Baseline.** Run `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts baseline` once (no change is needed; `sdlc.ts run` and `quality` need one, so never use them here). It runs each `fast`, `levels` and `quality` command once, writes already-failing `fast` commands into `knownRed` (the gate never blocks on debt it did not create) and prints each result. Tell the person its output: a failing level blocks verification until fixed, and a quality command that cannot count should be removed from `sensors.json` (that edit asks the person). Per-change base counts are measured later by the sensors node, against the base commit.
3. **Install (the default is standalone).** Run `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts init --full`, adding `--workflows` on the person's yes when the repo has a remote (it writes `.github/workflows/rig-check.yml` and `REVIEW.md`, never over an existing file). Skip `--full` only if the person said the team installs the plugin: then run `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts vendor` (CI runs that copy) and add `--workflows` separately. `--full` copies scripts, skills, agents and hooks into `.rig/bin` and `.claude/`, wires the git hooks and merges `templates/settings.json`. Say: the commands are `/rig:start`, `/rig:next`, and so on; the human gates are `/rig:approve` and `/rig:waive`; to upgrade, re-run `vendor --standalone` from a newer plugin; a teammate who never opens Claude Code runs `node .rig/bin/sdlc.ts hooks install` once.
4. **Verify.** List `.github/workflows/`, run `git remote get-url origin` and copy its output into the report verbatim (never retype or shorten a URL or owner), and report the workflows as installed, skipped by the person, or failed (with why). A missing remote means local-only PRs: say so. Some starter tools use the network (npm audit, semgrep --config auto, govulncheck, pip-audit, OWASP dependency-check); say so.
   Tell them: make `rig-check` a required check, add CODEOWNERS entries for `.rig/**` and the workflows, add an `SDLC_CONSUMERS_TOKEN` secret if a consumer repo is private, and `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`) or `ANTHROPIC_API_KEY` for the review.
5. **README.** Document rig in the repo's own `README.md` from `${CLAUDE_PLUGIN_ROOT}/templates/readme-rig.md` (architecture and user guide). **Brownfield:** keep the existing `README.md` and change only the block between `<!-- rig:begin` and `<!-- rig:end -->`: replace it if present, else append it at the end; with no `README.md`, create one with a title, a three-line summary from scout (a) and the block. **Greenfield:** create `README.md` with the project title, the goal, how to build, test and lint (the scaffold's commands), then the block. Never touch text outside the markers; under `--defaults` do this too (it is not a settings edit).
6. **Preflight.** Run `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts preflight --answers '<answers>'`, where `<answers>` is exactly this shape with the person's answers: `{"gates": {"M": ["design"], "L": ["spec", "plan", "design"]}, "valueRate": 100, "consumers": []}` (the keys are `gates`, `valueRate`, `consumers`; nothing else is accepted). It also closes init's onboarding window, so source written after it opens an ad-hoc change again. It runs every check and writes `.rig/PREFLIGHT.md`; fix each failed line it prints and rerun once; never loop.
End by telling the person to commit `README.md`, `.rig/`, `.claude/` and `CLAUDE.md` (make a first commit if the repo has none; ship and CI need a base), then: `Next: /rig:start "<first task>"` (the same in every install mode).
