# Prototype for $0 (adapted from Matt Pocock's `prototype`, MIT; rig keeps only the verdict, never the code)
1. **One question.** Run each sdlc.ts command as its own Bash call (no `cd`, pipes, redirects, `&&` or variables); read files with Read and Grep; one-line commit messages. Read `.rig/changes/$0/intent.md`; it must exist and be a spike (otherwise stop and tell the person to run `/rig:start` for the spike first). State the single question in one sentence at the top of `.rig/changes/$0/notes.md` under `## Question`. If reading code or docs settles it, stop: answer in `notes.md` (at most one page) and end. If `intent.md` or the person names logic/state or UI, take that branch; otherwise ask once when genuinely ambiguous.
2. **Pick the branch.** **Logic/state** ("does this model feel right?"): one self-contained HTML file at `.rig/changes/$0/prototype/logic.html` a non-developer can drive - controls that push the state machine through the hard cases, full relevant state rendered after every action, no build step, double-click to run. **UI** ("what should this look like?"): at least three radically different variants under `.rig/changes/$0/prototype/`, switchable from one place (URL search param or small index page), each labelled; reuse the project stack when it costs nothing, otherwise one static HTML file per variant.
3. **Throwaway rules.** Everything lives under `.rig/changes/$0/prototype/`, marked `PROTOTYPE - throwaway, do not ship` at the top of each file. No persistence by default (state in memory; a scratch file only when the question is about persistence, named `PROTOTYPE-wipe-me`). No tests, no error handling beyond runnable, no abstractions, no edits to production files. Trivial to run: one command or one double-click, recorded in `notes.md`.
4. **Run it and record.** Exercise the hard cases yourself (logic) or open each variant (UI); write what happened under `## Observed` in `notes.md` - what the state did, where it felt wrong, the concrete case that showed it. Surface state; do not summarise from memory.
5. **Verdict.** Under `## Verdict` in `notes.md`: the answer in at most five lines, plus the decision it settles for the follow-on change (interface, state shape, or UI direction) precise enough to cite from `design.md`. Prototype code stays uncommitted unless the person asks for a throwaway branch; never list it in a later change's `## Files` and never copy it into production - reimplement the decision cleanly. End with: `Next: <command from node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts next $0 --json>`.
