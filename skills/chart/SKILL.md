# Chart a sprint

`S` means `node --disable-warning=ExperimentalWarning ${CLAUDE_PLUGIN_ROOT}/scripts/sdlc.ts`. Run each command as its own Bash call.

1. **Which sprint, which PRD.** The person's PRD is accepted in any format and from any path; never reject it, ask for a template or tell the person to rewrite it. `$ARGUMENTS` may be `<N>`, `<N> <path>`, `<path>`, `sprint <N>: <path>` or `.rig/product/prd/sprint-<N>.md`. `N` is the number given, else the `sprint:` in the file, else the next number after the highest sprint in `.rig/product/` (0 when there is none). If there is no PRD at `.rig/product/prd/sprint-<N>.md` and no path was given, stop and ask for the PRD's path. If `.rig/sensors.json` is missing, stop and tell the person to initialise a greenfield repo first, giving the stack and goal from the PRD.
   **Base commit.** The chart branch needs a base for approve, the PR and CI to diff against. If `git rev-parse --verify HEAD` fails, or `git status --porcelain .rig/sensors.json CLAUDE.md` lists either file as untracked (`??`), init's output is not committed. Do not stop: ask once with `AskUserQuestion` ("Commit init's output on main as the base for this chart?", options yes or no). On yes: with no commits, `git checkout -b main` when the current branch is not `main`, then `git add -A`; with an existing `HEAD`, `git add README.md .rig .claude CLAUDE.md` plus the scaffold paths `git status --porcelain` shows as untracked; then `git commit -m "chore: rig init scaffold"` and carry on. On no, stop and say the chart needs that base.
   **Take it as given.** For a path elsewhere, write `.rig/product/prd/sprint-<N>.md` as a copy of that file, keeping its text and acceptance criteria word for word. The only additions are what rig reads: `sprint:` and `engineers:` (1 unless stated) in frontmatter, and a stable id on each requirement (`### FR-n:` heading or `| NFR-n |` row; keep the file's own ids, number the rest in order). Never invent a requirement, a number or an answer; put every unclear point under `## Open questions`.
   **Gap pass (you, no agent).** Read the PRD, `.rig/product/brief.md`, `.rig/product/architecture.md` and `.rig/sensors.json`, then list what a test could not assert yet: no technology (language, framework, datastore, hosting), no non-functional requirements (performance, security, availability, accessibility, scale), and ambiguities that change an expected value (rounding, formats, limits, ordering, units, error text, how a number is measured). Put them in one `AskUserQuestion` batch of at most 4 questions, each with the likely options and a free-text answer; with no gaps, skip the question. Do not ask what the PRD already states. Write each answer into `.rig/product/prd/sprint-<N>.md` marked `(answered at chart)`: technology under `## Integrations and constraints`, a non-functional answer as a numbered `NFR-n` row with the person's own target, anything else as a `Decisions` bullet under the requirement it refines. "You decide" is left for the architect's ADR and listed under `## Open questions`. Never invent an answer.
2. **Design.** Invoke `superpowers:brainstorming` with the PRD (and `.rig/product/brief.md`, `.rig/product/architecture.md` when they exist) as the opening material and one added line: the written design goes to `docs/superpowers/specs/<date>-sprint-<N>-design.md` and must end with `## Intents`, one line per intent as `- <slug>: <one-line scope> (<PRD ids>)`, and a `## Design` section a builder can draw `architecture.md` from. Let the skill run its conversation; offer recon and `anthropic-skills:deep-research` where it offers recon. Do not continue until the design doc exists.
   **Architect.** Launch `rig:architect` in the foreground with no model override (its frontmatter sets the generator model) and a brief of at most 40 lines:
   - the PRD path, the design doc path, `.rig/product/brief.md` and `.rig/product/architecture.md` when they exist, and the formats `${CLAUDE_PLUGIN_ROOT}/templates/intent-format.md` and `architecture-format.md`;
   - write `.rig/product/intents/<slug>.md` (slug of at least two characters, `estimate_days` 1 or 2, every behaviour citing a requirement the PRD defines, a `kind: boundary` intent naming its `Contract:` and `Example:` files), update `architecture.md`, fill `brief.md`, and add ADRs under `.rig/product/adr/`;
   - write `design: <repo-relative path>` of the design doc into `architecture.md` frontmatter, and write one intent per line of the design doc's `## Intents`, no more and no fewer;
   - sprint 0 always includes a `walking-skeleton` intent that every other intent depends on;
   - with code but no architecture document, read the code with read-only searches first.
   Its reply lists open questions: ask them in one `AskUserQuestion` batch, write each answer into the sprint PRD as in the gap pass, and relaunch the architect only when an answer changes an intent.
3. **Check.** `S chart check <N> --json`. Each `block` finding names the rule and the file. Make at most one fix round: relaunch the architect with only those findings, then check again. Never edit the PRD to make a finding go away.
4. **QA.** Launch one `general-purpose` agent in the foreground with model `sonnet`, brief of at most 40 lines as `/rig:testplan` gives it: read the PRD, the intents, `architecture.md` and `${CLAUDE_PLUGIN_ROOT}/templates/testplan-format.md`; write `.rig/product/testplan/plan.md`, `cases.md` and `data/`; every requirement gets a case citing its ids, an intent slug and a B-number; data is synthetic. Then `S chart check <N> --cases --json` with at most one fix round.
5. **Review.** Launch `rig:evaluator` in the foreground with no model override and the brief "review the chart bundle for sprint <N>", plus the `chart check` output and the design doc as a source. Write its reply to `.rig/product/chart-review.md`. On `changes-needed`, make one fix round: relaunch only the generator that owns each finding (architect or QA) with just those findings, then run both checks again. Do not review twice, and never edit the PRD to clear a finding.
6. **Commit.** `git checkout -b rig/chart-<N>` (or `git checkout rig/chart-<N>` when it exists), `git add .rig/product`, `git commit -m "docs: chart sprint <N>"`.
7. End with the intents (slug, requirements, days, dependencies), the review verdict with any finding still open, and `Next: review the branch, then a person runs /rig:approve chart-<N>`.
