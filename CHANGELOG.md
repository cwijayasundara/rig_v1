# Changelog

## Unreleased

- **`/rig:pr` reviews with the native `/code-review` and `/security-review`, on the delta, before the PR opens** (`docs/superpowers/specs/2026-10-21-native-review-design.md`). The review runs after verify and before `sdlc.ts pr`, so fixes land in one commit with `review.md` and one PR opens. `/security-review` needs an `origin` remote; without one a `general-purpose` agent does the security pass. `rig:evaluator` keeps chart mode only. `/rig:init` writes a `## Review` block into CLAUDE.md (the local `/code-review` reads CLAUDE.md, not REVIEW.md); `templates/REVIEW.md` is now for the managed GitHub service only.
- **An intent brief carries its design and its failure behaviour.** `templates/intent-format.md` gains `## Design` (a `| Part | Responsibility | Must not |` row per part the intent touches) and a `### Failure behaviour` subsection under `## Behaviours`; `templates/brief.md` gains the same subsection and a responsibilities table in `## Architecture`. Failure rules are B-numbered behaviours, so the existing trace, `spec.md` copy and test rules cover them. The architect fills both, and `/rig:plan` cites the design instead of restating it. `chart check` reports (does not block) a `kind: boundary` intent with no failure behaviour (`failure-behaviour`), and `npm run eval:chart` scores design and failure coverage. Modelled on Jain's application brief, whose resiliency rules are what an unharnessed model missed. Live A/B (Opus, 3 runs each): failure cases specified 9.3 → 16.0 per chart, recall unchanged, chart cost $1.09 → $1.29 (`eval/results/2026-10-17-chart-brief.md`). Covered by `scripts/chartcheck.spec.ts` and `eval/chart.test.mjs`.
- **The sprint outer loop returns, on the behavioural harness** (`docs/superpowers/specs/2026-10-17-sprint-outer-loop-design.md`). `/rig:chart <N>` (the `architect` agent, Opus) turns a PRD into intents with a brief each and the updated architecture; `/rig:testplan <N>` (Sonnet) writes the test plan, cases and data; `sdlc.ts chart check|report <N>` and `ready` are deterministic; `approve chart-<N>` is human-only and stale on any edit; `new <slug> --source <intent>` links a change to its intent and `sync --check` keeps `spec.md` faithful to it. Rules: every intent, behaviour and case traces to a PRD requirement; an intent is at most two engineer-days. New `models.design` role; the harness cap is 5,000 lines (scripts-only cap 3,450); e2e stage S6; `npm run eval:chart` scores charts against an answer key.
- **Subagents stay in the foreground.** `templates/settings.json` sets `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1`: a headless (`claude -p`) session backgrounds every Agent call by default ("Async agent launched"), so `/rig-start` ended its turn while the architect was still writing design.md and the build ended while its implementer ran. The live e2e driver now passes the template's env, not only its allow rules. Covered by `scripts/models.spec.ts` and `tests/e2e/driver/live.test.mjs`.
- **A refused follow-up names its waiver.** `pr --followup` runs the same ship gate as `pr` (shared `shipGate`, including the quality re-measure; commands excluded, verify ran them) before it commits, and a later successful follow-up push clears an earlier push failure. An over-limit review fix used to commit, fail in the pre-push hook and hard-block pr-review with "git push of the follow-up failed"; it is now a gate-kind block that names `/rig:waive size * <reason>`, so pr-review resumes once a person waives (R46). Covered by `scripts/pr.spec.ts`.
- **`## Files` may be a table.** `planFiles` reads the first cell of a markdown table row as well as `- path` bullets, and a `## Files` section with no paths is a plan problem (status warning, edit hook). A design with a Files table matched no files, so the model rewrote the approved design and staled its gate. Covered by `scripts/sdlc.spec.ts`.
- **The live e2e is timed.** `run.mjs` prints each phase's wall clock and, in a live run, fails when the whole run exceeds `--minutes` (default 20). An abort is recorded in report.md, not only on the console. The default live model is `claude-haiku-5-5`, and the S2 and S3 prompts name tier M. The operator waives a ship-gate block that is only about diff size, and nothing else. After approving the chart the test merges `rig/chart-0` into main, as the person merging the chart PR. The PRD states that `createHandler(catalog)` returns the handler function itself, and the hidden acceptance asks only that a bad price or quantity throws, as the PRD says (it required the word "positive"). The live step prompt no longer tells the model to "commit on the branch", which contradicted the build skill. The design check allows interface code blocks up to the harness's own 10-line limit (`LIMITS.planCodeBlockLines`) instead of failing on any fence. Timed live runs: 16.0, 15.1 and 13.8 min, about $1.20 each.
- **A clean round cannot record over a stall.** `ratchet record` refuses (exit 3) while the same node holds a cap, stall or budget block (other-kind blocks, such as a failed push, are fixed by rerunning their node and do not stop it): in a live run the reviewer's repeated finding stalled pr-review and the model recorded `verdict: pass` five seconds later, so a stalled change read as ready. Covered by `scripts/ratchet.spec.ts`.
- **The build runs only on `sdlc/<slug>`.** `/rig:build` switches to the change branch, creates it from the trunk, or stops on any other branch. A greenfield build ran on `rig/chart-0`, the branch `/rig:chart` leaves, so every slice record printed `"commit": null` and pr refused. Covered by `scripts/policy.spec.ts`.

Overhead: the harness no longer slows down as history grows, and never makes the model wait on display work.

- **Shipped changes are read with one `git ls-tree` of HEAD per process**, not a `git log -- <path>` per change. `status` used to run four history walks for every change ever made (fifteen for the active, unshipped one, which walks all of history to find nothing): 14 s and 507 git processes in a repo with 120 shipped changes and 3,000 commits, now 0.4 s and 13. A ship record deleted from HEAD after it was committed no longer counts as shipped.
- **`status --json --band`** returns only what the mod draws (the active change, step, story, sensors, flow), without the per-change warnings, open items and staleness, so it never stamps the tree. The mod uses it on every turn (0.2 s, one git process).
- **The mod's per-turn reads are lean.** Turn start and the band refresh use `--band` (0.2 s each instead of seconds that grew with every change shipped), and the design-gate check reuses the step from the band refresh instead of running `next --json`.
- **Edits start no extra process.** The impact dialog asks the script only when the active change has an `impact.json`. The per-edit `✓ sdlc` notice is gone: it cost a node start per edit and core clears a notice as soon as the call resolves. The settings post-edit hook still checks every edit.
- **Subagents run the recorder without a prompt in standalone repos.** The settings template allows `Bash(node --disable-warning=ExperimentalWarning .sdlc/bin/sdlc.ts *)`; skill `allowed-tools` grants last only for the invoking turn and are not documented to reach subagents, so the implementer and reviewer stopped for approval on every `sdlc.ts run`. The rule matches only that exact relative path (a plugin cache path, `env` or a non-safe variable assignment such as `SDLC_HUMAN=1 …` still prompts), but `run -- "<command>"` runs any command: see SECURITY.md. The reviewer's run command now uses the same form.
- **A reviewed change leaves a clean tree.** `pr-checks` clears `STATE.md` in the review-evidence commit once the change is done; before, `status` or `next` cleared it afterwards and left it modified after every shipped change.
- **The size sensor no longer judges the vendored harness** (`.claude/**`, `.sdlc/bin/**` and the other protected paths, which `harness-tamper` watches). Installing rig warned about long lines in `.claude/workflows/review.js`, and an upgrade that re-vendors the scripts counted toward `limits.diffLines`.
- **Onboarding writes `/rig-start` into CLAUDE.md's routing line**, the command a standalone repo has; `/rig:start` exists only with the plugin.
- **Pushing a finished change's branch no longer mints an ad-hoc change.** Once a change is reviewed nothing is active, so pre-push created an `adhoc-*` change for the branch's source, repointed `STATE.md` at it and, past three files, refused the push as an unplanned tier M change. That is the push a person makes after `/rig-pr-review` commits its evidence. A push now belongs to the change whose folder its diff carries (the branch's own first), as in CI.
- **`init --stack` declares the `api` level** (the unit command, like `acceptance`). An endpoint change requires it, and `--defaults` onboarding may not declare levels itself. So an endpoint change in a repo onboarded with `--defaults` blocked at test, and declaring the level then was a mid-change `sensors.json` edit that trips `harness-tamper` and needs a human waiver. Point `acceptance` and `api` at a real e2e or HTTP test when you have one.
- The implementer no longer pipes the recorder through `tail` (the recorder prints only the last lines), so each test run is one plain command.

## 0.6.0

Scale: monorepos, large repos and a cleaner view of where work stands.

- **Scopes.** `sensors.json` gains `scopes` (glob to `{ name, root, fast, full, quality, deps }`), `scopeLimit`, `ci.scope` (`affected` or `all`), an optional `affected` command and `sparseBase`. A diff selects the scopes it touches plus their dependents (declared `deps` edges only, no import parsing); `fast` and `full` run per scope in its root, quality is measured per scope on both sides, shards group by scope, and a diff spanning more than `scopeLimit` scopes is re-tiered to L. Files outside every scope run the top-level commands and raise an `unscoped` warning. CI selects from the diff and the base branch's config, and `ci.scope: "all"` runs everything. A repo with no `scopes` behaves exactly as 0.5.0. A scope's `levels` and the red-proof test command stay top-level until 0.7.
  - Scope roots must be relative and inside the repo; a root whose real path resolves outside it blocks (`not run`). The same command text in the same resolved directory runs once.
  - The `affected` command fails closed: if it fails or times out, every declared scope is treated as affected and an `unscoped` warning says so. Its stdout is read in full.
  - `verify` with no resolvable base ref runs every scope's commands, so a clean tree can never stamp `full: pass` with nothing run.
  - With scopes declared, a source-less diff (docs or harness only) runs no scoped or top-level commands at edit, commit and CI, while `verify` (which gates the ship stamp) runs the top-level commands.
  - Weakening edits (blocked unless a person approves) include: removing a scope or a `deps` edge, raising `scopeLimit`, switching CI from `all` to `affected`, changing, removing or emptying a scope's `fast`, `full` or `quality` command, changing a scope root, and, when the base already declared scopes, adding a scope glob that lacks a `fast`, `full` or `quality` command of a kind the base runs (top-level or in any scope).
  - `sparseBase` (opt-in) measures the base in a throwaway worktree with a cone sparse checkout of the affected scopes and their `deps` closure. The patterns go to that worktree's own `info/sparse-checkout`; your `.git/config` is never modified. Roots are validated, and an invalid root or any sparse failure falls back to a full checkout. It relies on correct `deps`: a scope tool that reads paths outside its declared closure can fail or over-count on the sparse base and hide a regression, so declare `deps` completely or leave `sparseBase` off. The base-count cache is keyed on scope root and sparse or full mode.
- **Preflight.** `/rig:init` runs `sdlc.ts preflight`: every check runs and one report is written to `.sdlc/PREFLIGHT.md` (stack, toolchain against the build's own source of truth such as the Maven parent chain, `.nvmrc`, `go.mod`, `pyproject`, whether declared commands resolve, base and tree state, remote reachability with one HTTPS retry, consumer clones, the evidence deny rules). The suite is never run by it. `status` flags a missing or older report.
  - The report is advisory. Only the script writes it (`templates/settings.json` denies Edit and Write on it), but a Bash redirect could still forge it, so nothing trusts its `result:` line: only `status` staleness and the start skill read it.
  - It checks the repo root only; the toolchains of individual scopes are not checked.
  - Host probes: `java`, `go` and `python3` version probes run in the project root with `GOTOOLCHAIN=local`, so `go` never downloads a toolchain. SSH reachability takes `core.sshCommand` only from your global or system git config and runs `ls-remote` outside the repo, so a clone's own config never runs; the base-state check runs with `core.fsmonitor` off. A relative-path local `origin` reports not reachable.
  - A repo set up before 0.6.0 fails the protection check until `init --full` is rerun (it adds the `PREFLIGHT.md` deny rule). `PREFLIGHT.md` holds host versions, so it is a per-host artifact: consider gitignoring it.
- **`status`.** It now shows `where:` and `stale:` lines, lists open questions from intent, design and plan, and warns when a slice lists more than five files. Stale means: design older than intent, plan older than design, a verification made on another tree, or a preflight older than the config or a manifest. `approve design` refuses open questions in `intent.md` too.
- **Slice checkpoints.** A recorded build slice is committed on `sdlc/<slug>` by the script (`commit --only` with literal pathspecs for that slice's planned files, deletions and renames included; `--no-verify`; never a push; never on the trunk). A failed commit reopens the slice and appends a `reopened` event.
- **CI report.** `check.ts` at the CI point lists up to five warnings, also in the step summary (backticks neutralised).
- **Lane events.** `SubagentStart` and `SubagentStop` are registered again as `async` observational hooks that append lane events; the scorecard shows work, span and idle (gaps over `idleGapMs`, 15 minutes by default).
- **Size at write time.** A file that crosses `limits.fileLines` is blocked at edit, Stop and commit (it still warns at ship and CI).
- **Story points.** Every change has points: S 5, M 7, L 11 by default (`points` in `sensors.json`), or an explicit number set with `new --points N` or `sdlc.ts points <slug> <N>`, kept in `ratchet.json` (not in the model-writable `intent.md`). Status and the scorecard show them; `metrics` reports shipped points, velocity per week and cost per point (unmeasured below five shipped changes).
- **Size.** The harness line cap is now 6900 (it was 5910): this release adds features, so it is not a net reduction.


## 0.5.0

Do each thing once, and follow the official plugin pattern. This release also carries everything that was listed as unreleased after 0.4.1 (the last section below).

- **Stamp, don't re-run.** `verify` now also runs the declared `full` commands and stamps `verification.md` with `tree:`; `sensors` stamps its node the same way. The stamp is a `git write-tree` of the working tree (tracked and untracked files, ignored files left out) with `.sdlc/` removed, plus the hashes of `sensors.json` and `rules.json`. It is computed from a temporary index whose mtime is copied from the real index, so git's racy-clean handling cannot trust a stale cached blob. Because it is a tree hash, it is the same before and after `/rig:pr` commits. Ship and pre-push skip the full commands and the quality comparison only when the stamp matches; a stale or missing stamp (including a repo with no commit) re-runs exactly as before, so no existing flow can start failing. Pre-push skips only for a non-ad-hoc change pushed from a clean checkout whose stamp matches (the clean check passes `--untracked-files=all`, outside `.sdlc/`). CI never reads a stamp.
- **One model review per change.** Tier S and M slices are verified by `ratchet record <slug> build --checks` (a green declared test run on the current tree, no sensor block, every file in `## Files`); tier L keeps a Sonnet slice review. `pr-review` reviews once; a large tier L diff is split by `sdlc.ts shards` (at most 25 files and 5,000 changed lines each) and reviewed by the `rig-review` workflow with a referee per finding. `security-review` runs only when the intent's risks name it.
- **The review workflow does not trust its reviewers.** `rig-review` validates every reviewer finding as untrusted input (shard membership, severity, category, line). Its verdict is `pass`, `changes-needed`, `disputed` or `incomplete`, with the fields `unreviewed`, `disputed`, `discardedBlocking` and `discardedMalformed`. It never reports `pass` when files were unreviewed, when findings were discarded as malformed (a discarded finding that claimed or hid a blocking severity makes the verdict `incomplete`), or when a referee disputed a critical or high finding (that finding is kept and the verdict is `disputed`; only medium findings a referee cannot re-derive are dropped). `injection` and `security` findings are never refereed. The script builds the shell commands itself (`git --literal-pathspecs diff '<base>' -- '<path>'`); a path containing a quote, a backslash, or a control or bidi character is refused and reported as unreviewed. Deleted files are reviewed.
- **Faster and smaller.** The test-count invariant reads only the diff's test files, the base side in one `git cat-file --batch`. Quality and red-proof share one base-checkout helper (`basetree.ts`, sparse checkout available).
- **The guard layer is gone**. Removed: the `PreToolUse` hooks for Bash and for Edit (`pre-bash`, `pre-edit`), the `SubagentStart` and `SubagentStop` gates, auto-approval, and the read-only Bash allowlist for scout and reviewer (their `tools:` lists remain). Replaced by: `deny` rules in `templates/settings.json` for pure evidence (approvals, waivers, `usage.jsonl`, `.gate`, `.baseline`, `unresolved.json`, and per change `runs.jsonl`, `verification.md`, `impact.json`, `ratchet.json`, `events.jsonl`, `pr.md`, `ship.json`) and `.env`; `ask` rules (a person is prompted) for `sensors.json`, `rules.json`, `.claude/settings.json`, `.sdlc/bin`, `.sdlc/githooks`, `.sdlc/mod`, `.sdlc/guides`, the `rig-check` workflow and CODEOWNERS; and CI, which recomputes every verdict from the base branch's checker. Rule semantics were checked against the Claude Code docs: deny wins over ask, ask over allow, and a `/path` pattern in project settings anchors at the project root. `CLAUDE.md` is deliberately not ask-protected, because `init` writes it with the Write tool and an unattended init would fail. The deny patterns do not cover case-folded paths on case-insensitive file systems (CI recomputes). A `changes/*/preflight` deny arrives with preflight in v0.6. **Auto-approval was removed and 0.5.0 does not ship the `permissions.allow` rules the spec described**, so declared commands (the test command that `build`, `verify` and the stamp run) now prompt unless you run Claude Code in auto mode or add your own `allow` rules for them; unattended and autonomous builds depend on auto mode (or your allow rules) until a later release writes those rules from `init`. The `auto-approved` counters in the scorecard, metrics and band are a known leftover that always read 0 now (nothing emits `auto-approve` events). Re-running `vendor --standalone` now removes the retired hook entries from every event. No hook runs on Bash. Guide injection moved to the slim `post-edit` hook. No longer prompted at edit time: files outside the plan's `## Files` (still judged at ship and CI), tier L bugfix edits before plan approval (the `next` gate still holds), consumer-repo edits.
- **Unplanned work is still fully checked.** `post-edit`, Stop, the git hooks and CI run every sensor with no active change (`scripts/vibe.spec.ts` pins this at edit, stop, commit and CI). `editFindings` now also runs the layering sensor, so unplanned work meets the architecture rules at write time.
- **Size.** The harness line cap is now 5910 (measured 5906; it was 6060).
- **Residual risk.** A shell script can still write a file locally, and the model can still run `SDLC_HUMAN=1 ... approve` through Bash. CI refuses approval rows a PR adds unless an independent reviewer approves the head commit, and recomputes every verdict from the base branch's checker. CI plus branch protection is the boundary.
