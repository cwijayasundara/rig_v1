- **Question/problem:** Why did one week of building this repo cost about $1k and ~3 h per change, and how to make it fast and cheap?

## superpowers/specs/2026-10-16-behavioural-harness-design.md  (2026-10-16, 18213 chars)
- **Problem:** rig had a language-specific sensor config, tiers, slices, points and spend, and a heavy lifecycle. It needed a language-free behavioural harness on native Claude Code primitives, with an outer loop that proves the harness lifts a model.
- **Design:** One registry per target repo, `.rig/sensors.json`: `stack`, `gates{plan,merge}`, `contracts{files,validate,run}`, `models{build,evaluate}`, `sensors[]`, `policy`. A sensor has `id`, `cmd` (`{files}` is substituted at edit cadence) or `builtin`, `cadence` (edit|turn|commit|ci|nightly; a sensor also runs at every later cadence), `blocks`, `count` (exit|lines|json:path; non-exit counts are ratcheted against base), `guide` (one sentence), `timeoutMs` (60s at edit/turn, 600s at commit/ci).
  - Built-ins: secrets, test-tamper, suppression, harness-tamper, size, layering, rules, red-proof, traceability, plus new model-role. Removed: tier, adhoc, unscoped, contract-impact.
  - Policy per model family: `continuous` (all cadences in-session) or `final` (only secrets and harness-tamper at edit/turn, the rest at commit). CI always runs everything.
  - Model detection: hooks do not carry the model, so rig records it per session_id in `.rig/state/model.json` from the PostModelSwitch hook, SessionStart, the last assistant message in the transcript, then the pinned model.
  - Roles: build=sonnet (main thread and implementers), evaluate=opus (one read-only `agents/evaluator.md`). Role mismatch is a warning.
  - Stack packs `templates/stacks/<stack>.json` (node, angular, python, go, rust, java-maven, java-gradle, dotnet) with markers, sensors and contracts. `rig init` copies one into the registry. Specmatic is the default contract tool and needs Java.
  - `rig sync` renders each sensor's `guide` into a hashed managed block in CLAUDE.md. `sync --check` fails on an empty guide, an unknown sensor, a hash mismatch, or an untested brief behaviour.
  - Contracts are declared as globs, frozen by hash in `approval.json` at plan approval, and validated before run. Run joins the turn cadence only when the diff touches contract-covered source.
  - Hooks: PostToolUse edit, Stop turn (max 2 block attempts), git pre-commit/pre-push, SessionStart, PostModelSwitch, Agent launch, UserPromptSubmit (the human-only approve/waive recorder).
  - Slim lifecycle under `.rig/changes/<slug>/`: intent.md, spec.md, plan.md, approval.json, verify.json. Seven skills: start, plan, build, test, pr, rule, init.
  - Eval runner `eval/run.mjs`: five arms (Haiku+rig continuous, Haiku bare, Sonnet bare, Opus bare, Haiku+rig final), 10 runs each, hidden acceptance, results table committed.
- **Why this and not the alternatives:** The core stays language-free, so tool names live only in stack packs (a deny-list spec enforces it). The model is recorded by rig because hooks and env vars do not carry it. The contract is any executable spec, not only OpenAPI. Cut as unmeasured inventions: tiers, slices, points, spend ledger, metrics, UI mod, brain, 15 skills. Review findings advise and never block alone. Specmatic is the contract default despite the Java dependency.
- **Contracts/invariants:** Core scripts name no language or tool. Approvals go stale on a hash change. `rig waive` is human-only and recorded. CI judges with the base branch's checker and registry. Reserved finding ids: commands, config, contracts, unscanned, plan-gate, human-approval, sync. Frozen-file assertion loss is a test-tamper block. A rig-driven repo's main thread runs on `build`; the rig repo itself may use any model.
- **Outcome:** Built in 6 steps, each with `npm test` green. Step 1 registry and packs (4e54bdd, ef0b73d). Step 2 hooks, model recording and evaluator (c90e340, 3417a4d, 77dd30b). Step 3 contracts, freeze and sync (1a29bb5, 3170966). Step 4a deletions (72c8988, 4244194). Step 4b slim lifecycle (2c0d9c1, d3c7fb6, 1f7d519). Step 4c core reads the registry (79fd154, 224bd16). Step 5a merge aaeac2b and 5b merge d827b60 (e2e stages). Per-sensor ids merge e921750. Step 6 eval runner merge fe117d4.
- **Still open:** Specmatic jar licence unconfirmed (and Java needed locally); Specmatic blocked in practice, the shop contract uses a zero-dependency script. `PostModelSwitch` firing for `/model` and settings-pinned models is to be confirmed by a spec. A brief behaviour no change claims stays a warning only. Per-component lift needs ablation arms.

## superpowers/specs/2026-10-17-sprint-outer-loop-design.md  (2026-10-17, 17400 chars)
- **Problem:** rig covered one change from intent to merge, but nothing turned a large sprint PRD into traced, sized work. The outer loop had been cut on 2026-10-16 with no measurement behind the cut.
- **Design:** `/rig:chart N` runs in one turn: an Opus architect agent writes intents, a brief per intent, `architecture.md` (max 200 lines) and ADRs. Then `chart check N` (a script, 0 tokens), then at most one fix round. `/rig:testplan N` (Sonnet QA) writes plan.md, cases.md and data/. After that a person runs `/rig:approve chart-N`, once per sprint.
  - Artefacts under `.rig/product/`: prd/sprint-N.md (FR-n/NFR-n ids), brief.md, architecture.md (ends with `## Concerns` and `## Open questions`), adr/NNNN-*.md, intents/<slug>.md, testplan/.
  - Intent frontmatter: sprint, `prd:[ids]`, `depends:[]`, `estimate_days` 1|2, `kind` boundary|internal, owner, status. Sections: Intent, Non-goals, Design (Part|Responsibility|Must not), Interfaces, Behaviours with `### Failure behaviour`, Tests required. Behaviours are `- B1 (FR-3): …`.
  - Trace chain: FR/NFR -> intent -> behaviour (`slug#B1`) -> test case TC-n -> test (traceability sensor) -> verify.json. cases.md row: `| ID | Requirement | Intent | Behaviour | Level | Data | Expected |`.
  - `chart check` blocks on: untraced intent or behaviour, unknown id, requirement with no intent or no case, case with no requirement or a missing data path, estimate missing or >2, bad or cyclic depends, boundary intent with no contract or example, unresolved Concerns or Open questions. It only reports on: capacity over 10 days per engineer-slot, and progress gaps.
  - `approve chart-N` is human-only, refuses while any block stands, and its digest covers the PRD, architecture, ADRs, testplan, intents and their contract files (editing any makes it stale).
  - Lifecycle links: `S new --source <intent>` refuses an unready intent; `/rig:start` copies the intent's behaviours into spec.md; sync fails if spec.md drops one or adds one with no requirement; shipped = verify.json committed and PR merged; `rig next` lists ready intents.
  - Measurement: coverage, size accuracy (estimate against git actuals), rework (chart stale count), chart cost; an `eval:chart` task scores against an answer key (recall, invented-intent rate, size and cycle correctness), Opus vs Sonnet architect, with vs without the per-intent brief.
  - The agent is restored as `agents/architect.md`; skills `chart` and `testplan`; `scripts/chart.ts`. Budget about 800 lines; harness cap raised 3,900 to 5,000.

## superpowers/specs/2026-10-17-wiki-design.md  (2026-10-17, 9367 chars)
- **Problem:** Engineers onboarding, reviewing or planning need to understand how the parts of a codebase fit. A 2026-10-17 eval (Haiku, 37-file fixture, 6 questions) scored 6/6 on both native Grep/Read and an oracle index, so a search index shows no lift. Value lies in understanding, and the failure modes are wrong claims and stale content.
- **Design:** A DeepWiki-style committed wiki, `.rig/wiki/<page>.md` plus `index.md` and `state.json`, steered by `.rig/wiki.json` (repo `notes`; pages with title, purpose, parent, notes, paths; at most 30 pages; if absent a first pass proposes one and stops for editing).
  - Every body sentence must end with a citation: `[path#symbol]`, `[path]`, or `[adr:NNNN]` / `[commit:sha]` / `[pr:N]` for "why". Line ranges are not allowed. Diagram nodes and edges cite symbols.

A "cite every sentence" rule makes the check deterministic with no model deciding what is factual. Symbol hashes rather than file hashes stop unrelated edits flagging pages. Status lives in the PR comment, because a committed banner would dirty the tree. No CI-opened refresh PRs in v1 (needs an API key outside a session). No "why" from imagination.
- **Contracts/invariants:** Failure modes to avoid: a page with an unsupported claim, a refresh that rewrites unchanged pages, a PR check that blocks on wiki staleness, and cost exceeding value. Wiki commits go through the normal change flow. Wrong pages are fixed by fixing the generator, then regenerating. State is written only by `build` and `refresh`.
