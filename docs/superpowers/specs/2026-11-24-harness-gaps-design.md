# Harness gaps from the rig_v1_test run: design (short)

Source: manual run of add-item, view-item and the start of list-items in rig_v1_test, 2026-11-24.

## Intent
Five places where the harness lost or hid information, or stopped where it should continue. Each is fixed in the harness (skill text or script), with a spec that fails without it, then rig_v1_test is regenerated by `/rig:upgrade`, never hand-edited.

## Goals
- A review finding left open for a person reaches the carried file or the backlog, so it is read again.
- The PR evidence says "not run here" for a check that did not run, instead of "pass".
- The agent list names the model each agent really ran on.
- `/rig:start` runs on into `/rig:plan` (and build, test) in the same turn.
- A re-freeze that dropped nothing is reported as a re-freeze, not as a weakened test.

## Non-goals and anti-goals
- No new gate, hook, refusal or required field: everything here only routes, labels or continues. A person can still stop, override or ignore.
- No new file, command or module: each fix extends the function that already does that job.
- Not in this change: the stale CLAUDE.md map in a target repo, the tier-2 interrogation flag, the approval gate without a remote.

## Root causes (read from the code)
1. `scripts/carry.ts` `reviewItems` reads only `## Deferred` and `## Unverifiable`. A `## Findings` bullet "left open for a person" is never routed.
2. `scripts/prbody.ts` `headChecks` prints `pass` for any exit 0. The "not enforced here / does not run here / could not scan" echoes (stack packs) exit 0.
3. `scripts/prbody.ts` `agentsNote` prints `r.model ?? 'unknown model'`; the launch hook records no model, the resolved one sits in `.rig/state/model.json` by launch id.
4. `scripts/prbody.ts:151` flags every later freeze row as "weakened test".
5. The start skill already says "continue with `/rig:plan <slug>` in this turn" (spec: autoloop.spec.ts), but the model treats a slash command as something the person types and stopped ("Next, /rig:plan list-items. I haven't run it"). `build` and `test` chain the same way yet lack `Skill` in allowed-tools.

## Approaches considered
- A. Extend the existing function for each gap (chosen): smallest, no new concepts.
- B. A new "open items" file and a Stop hook that blocks until chained or routed: adds a mechanism and a restriction; rejected.
- C. Fix only the wording and leave the rest: leaves lost findings and misleading evidence.

## Design (chosen: A)
1. `reviewItems` also reads `Findings`; `RESOLVED` already skips `→ fixed`. Routing, dedupe and the backlog line format are unchanged.
2. One exported `NOT_RUN_HERE` regex in `scripts/sensors.ts`; `headChecks` prints `not run here` when the tail matches; the stack-pack spec asserts every guarded echo matches it.
3. `pr.ts` fills a null `AgentRow.model` from `readModelState(...).launches` by id (`resolved ?? requested`) before building the body.
4. The flag says `re-frozen: <why>`; `weakened test` stays for a row with `dropped`.
5. Chain steps say "call the Skill tool with skill `rig:plan`, args `<slug>`, in this turn (not a command for the person to type)"; add `Skill` to build and test allowed-tools.

## Left to the builder
Exact regex alternatives for 2 (taken from the pack texts), exact wording of 5.
