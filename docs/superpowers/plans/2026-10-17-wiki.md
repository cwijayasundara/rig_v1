# Code Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A committed, cited, hash-checked wiki of a target codebase that rig builds on `init`, reports as stale (warn only), and refreshes on request.

**Architecture:** Pure, model-free modules do everything checkable (citation parsing, symbol hashing, validation, staleness). One model-facing module (`wikigen.ts`) takes an injectable `Runner` so it is tested with a fake; the real runner shells out to `claude -p` like `scripts/evals.ts`. `wiki.ts` is the CLI, wired into `sdlc.ts` as `wiki <init|build|status|verify|refresh>`.

**Tech Stack:** TypeScript run by Node ≥22.18 (`.ts` imports with the `.ts` extension), `node:test`, `node:crypto`, no new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-17-wiki-design.md`

## Global Constraints

- Pages live in `.rig/wiki/<slug>.md`; steering file `.rig/wiki.json`; state `.rig/wiki/state.json`; index `.rig/wiki/index.md` (spec §Files).
- Page cap 30. Models: Sonnet for planner, writer and claim reviewer; never Opus (spec §Models).
- Every page-body line ends with a citation; citation forms are exactly `[path#symbol]`, `[path]`, `[adr:NNNN]`, `[commit:<sha>]`, `[pr:<number>]`. Line ranges (`#a..b`) are rejected.
- Hash = sha256 of the declaration text, comments stripped, whitespace collapsed; file citation hashes the normalised file. "Why" citations are never stale.
- `wiki status` and `wiki verify --no-review` write nothing. Staleness is warn-only: no command in this plan exits non-zero because a page is stale.
- No CI job in v1. TS/JS symbol resolution only; other languages cite files.
- Match `scripts/` style: one comment line at the top of a file saying what it is, small pure functions, `*.spec.ts` beside each file. Verify with `npm test` and `npm run typecheck`; quote the output.
- Per `CLAUDE.md`: never hand-edit generated wiki pages in a target repo; fix the generator.

## Review Focus

1. A symbol declared twice in one file (overloads, shadowed names): resolve to "unresolved", never to the first match.
2. A cited file deleted or renamed: `status` reports the citation as missing and the page stale; it does not crash.
3. A citation path that escapes the repo (`../x`, absolute) in model output: rejected by validation.
4. Abbreviations and decimals inside a line ("e.g.", "v1.2") must not read as two sentences; CRLF pages parse the same as LF.
5. A page with zero citations and a `wiki.json` with a parent cycle or duplicate titles: clear error, not a hang or a pass.

### Task 1: Citations and symbol hashing

**Files:**
- Create: `scripts/wikicite.ts`, `scripts/wikicite.spec.ts`

**Interfaces:**
- Produces:
  - `type Cite = { kind: 'code'; path: string; symbol?: string } | { kind: 'why'; type: 'adr' | 'commit' | 'pr'; ref: string }`
  - `parseCites(line: string): Cite[]` (trailing citations of a line, in order; `[]` if the line does not end with one)
  - `findSymbol(source: string, symbol: string): string | null` (the declaration text, or `null` when absent or declared more than once)
  - `normalise(text: string): string` (comments stripped, whitespace collapsed)
  - `hashText(text: string): string` (first 16 hex chars of sha256 of `normalise(text)`)
  - `citeHash(cite: Cite & { kind: 'code' }, read: (p: string) => string | null): string | null` (`null` = unresolved or missing)

- [ ] **Step 1: Write failing tests** in `wikicite.spec.ts`: `parseCites` parses `[src/a.ts#f]`, `[src/a.ts]`, `[adr:0003]`, `[commit:ab12cd3]`, `[pr:42]`, two trailing cites on one line; rejects `[src/a.ts#1..5]`, `[../x.ts]`, `[/etc/passwd]` (returns `[]`). `findSymbol` finds an exported function, an arrow `const`, a class, an interface, and a method inside a class by bare name; returns `null` for a name declared twice and for a missing name. `hashText` is equal across whitespace and comment changes inside the declaration and different when a token changes. `citeHash` returns `null` when `read` returns `null`.
- [ ] **Step 2: Run** `node --disable-warning=ExperimentalWarning --test scripts/wikicite.spec.ts`. Expected: FAIL (module not found).
- [ ] **Step 3: Implement** the five exports in `scripts/wikicite.ts`. `findSymbol` is a regex over declaration keywords (`function|class|interface|type|enum|const|let|var`, optional `export`/`default`/`async`) plus class-method heads; the end of the span is brace matching that skips string and template literals, or the first `;`/line end when no brace opens. Count matches first; more than one means `null`.
- [ ] **Step 4: Run** the spec again. Expected: PASS.
- [ ] **Step 5: Commit** `git add scripts/wikicite.ts scripts/wikicite.spec.ts && git commit -m "feat(wiki): citations, symbol spans and hashes"`

### Task 2: Page validation (deterministic)

**Files:**
- Create: `scripts/wikivalidate.ts`, `scripts/wikivalidate.spec.ts`

**Interfaces:**
- Consumes: `parseCites`, `citeHash` from Task 1.
- Produces:
  - `type WikiFinding = { rule: 'uncited' | 'two-sentences' | 'path-missing' | 'symbol-unresolved' | 'path-escapes' | 'why-unresolved' | 'mermaid'; line: number; message: string }`
  - `type PageEnv = { read: (p: string) => string | null; whyExists: (c: { type: 'adr' | 'commit' | 'pr'; ref: string }) => boolean }`
  - `validatePage(text: string, env: PageEnv): WikiFinding[]`
  - `pageCitations(text: string): { line: number; cite: Cite }[]` (every cite on the page, used by state and status)
  - `bodyLines(text: string): { line: number; text: string }[]` (non-blank body lines outside front matter, headings and plain code fences; `mermaid` fence lines are included and tagged by validate)

Line rule (this plan's decision, implementing the spec's "every sentence ends with a citation"): one sentence per line, and each body line ends with a citation. Exempt: front matter, headings, blank lines, a single leading `> purpose` line, fenced non-mermaid code. Inside a `mermaid` fence every non-blank, non-header line must end with a `%% [cite]` comment.

- [ ] **Step 1: Write failing tests**: a clean page returns `[]`; each rule fires on its own line number — an uncited bullet, a line with two sentences (`. ` followed by a capital) but not `e.g. foo` or `v1.2 is`, a missing path, an unresolved symbol, `[../x.ts]`, an unresolvable `[commit:deadbee]`, a mermaid line with no `%% [cite]`. CRLF input gives the same findings as LF. A page of only headings returns `[]`, and `pageCitations` returns `[]` for it.
- [ ] **Step 2: Run** `node --disable-warning=ExperimentalWarning --test scripts/wikivalidate.spec.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** the three exports in `scripts/wikivalidate.ts`.
- [ ] **Step 4: Run** the spec. Expected: PASS.
- [ ] **Step 5: Commit** `feat(wiki): deterministic page validation`.

### Task 4: Model steps behind a Runner

**Files:**
- Create: `scripts/wikigen.ts`, `scripts/wikigen.spec.ts`

**Interfaces:**
- Consumes: `validatePage`, `WikiConfig`, `snapshot`.
- Produces:
  - `type Runner = (req: { role: 'plan' | 'write' | 'review'; prompt: string }) => { text: string; usd: number }`
  - `claudeRunner(model?: string): Runner` (spawns `claude -p --output-format json --model <sonnet id>` with the env scrub that `evals.ts` uses; reads `total_cost_usd`; throws a readable error when `claude` is missing or exits non-zero)
  - `planConfig(files: string[], run: Runner): { config: WikiConfig | string; usd: number }`
  - `writePage(page: WikiConfig['pages'][number], sources: Record<string, string>, run: Runner, hint?: string): { text: string; usd: number }`
  - `type Verdict = 'supported' | 'unsupported' | 'contradicted'`
  - `reviewPage(text: string, sources: Record<string, string>, run: Runner): { verdicts: { line: number; verdict: Verdict }[]; usd: number }`
  - `dropClaims(text: string, verdicts: { line: number; verdict: Verdict }[]): { text: string; dropped: number; total: number }`
  - `buildPage(args: { page; sources; env: PageEnv; run: Runner; maxDropShare?: number }): { text: string | null; findings: WikiFinding[]; dropped: number; usd: number }` — write, validate (one rewrite with the findings as `hint` if any), review, drop; if the dropped share exceeds `maxDropShare` (default 0.3) regenerate once, then return the result with a finding instead of throwing. `text` is `null` only when validation still fails after the rewrite.
  - `estimateUsd(pages: number, sourceChars: number): number` (pre-flight; per-million-token rates live in one constant table `PRICE_PER_MTOK` — confirm Sonnet's current rates with the `claude-api` skill before filling it in)

- [ ] **Step 1: Write failing tests** with a scripted fake `Runner`: `buildPage` returns a clean page and sums `usd` across calls; a first write with an uncited line triggers exactly one rewrite whose prompt contains the finding; a review that marks 2 of 4 lines `unsupported` drops those lines and regenerates once; a second bad result is returned with a finding and no third call; `reviewPage` ignores verdicts for line numbers that are not claim lines and treats an unparseable reply as an error string, not as `supported`. `estimateUsd(0, 0) === 0` and grows with both arguments.
- [ ] **Step 2: Run** `node --disable-warning=ExperimentalWarning --test scripts/wikigen.spec.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** the exports in `scripts/wikigen.ts`. Prompts state the line rule (one sentence per line, each ending in a citation, "why" only with an ADR/commit/PR citation) and say to cite only the files supplied.
- [ ] **Step 4: Run** the spec. Expected: PASS.
- [ ] **Step 5: Commit** `feat(wiki): page writing and claim review behind a Runner`.

### Task 5: The `wiki` command

**Files:**
- Create: `scripts/wiki.ts`, `scripts/wiki.spec.ts`
- Modify: `scripts/sdlc.ts` (register `wiki` in the command table at line ~258, import `cmdWiki`)

**Interfaces:**
- Consumes: Tasks 1–4; `ROOT`, `read`, `out`, `fail`, `git` from `scripts/core.ts`.
- Produces: `cmdWiki(args: Args, run?: Runner): void` handling `init`, `build [--page <title>] [--max-usd N]`, `status`, `verify [--no-review]`, `refresh [--max-usd N]`.

Behaviour (spec §Commands, §Against stale content):
- `init` writes `.rig/wiki.json` from `planConfig` over the tracked source files, refuses to overwrite an existing one, and prints `edit .rig/wiki.json, then run: wiki build`. It builds no pages.
- `build` fails with a clear message when `wiki.json` is missing or `parseWikiConfig` errors. It prints the `estimateUsd` figure first; with `--max-usd` smaller than the estimate it exits non-zero before any model call. It writes pages, `index.md` and `state.json` (committing nothing), and prints total `usd`.
- `status` prints one line per stale citation (`page: cite (why)`) and `wiki: N stale page(s)` or `wiki: fresh`; it exits 0 either way and writes nothing.
- `refresh` rebuilds only pages `wikiStatus` lists, passing `git diff <builtAt>..HEAD --stat` for the cited files as a hint, then validates and reviews as `build` does.
- `verify` runs `validatePage` on every page and, without `--no-review`, `reviewPage`.

- [ ] **Step 1: Write failing tests** in `wiki.spec.ts` in a temp git repo (see how `scripts/initbaseline.spec.ts` builds one) with a fake `Runner`: `init` writes a parseable `wiki.json` and a second `init` fails; `build` over a two-page config creates both pages, `index.md` and `state.json`, and `status` then prints `wiki: fresh`; after editing one cited symbol `status` names only that page and `git status --porcelain` is unchanged by running it (read-only); `build --max-usd 0.0001` exits non-zero and the fake runner was called 0 times; `refresh` calls the runner only for the stale page.
- [ ] **Step 2: Run** `node --disable-warning=ExperimentalWarning --test scripts/wiki.spec.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** `cmdWiki` and register it. Pages are written with a trailing newline and LF endings.
- [ ] **Step 4: Run** `npm test` and `npm run typecheck`. Expected: all pass (quote the summary line).
