# Journey e2e Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command (`npm run e2e`) drives rig through init, chart, approve and build for a greenfield sprint and a brownfield sprint on one sandbox repo, has a Sonnet inspector judge the artefacts after every step, and logs and alerts on violations without a person in the loop.

**Architecture:** A stage table (act, deterministic gate, rubric) is run by a small orchestrator. Act reuses `createSessions`/`liveDriver` (Haiku). The inspector and the approval reviewer are read-only Sonnet sessions that return schema-checked JSON. Violations go to `violations.jsonl`, are matched against `triage.json`, and are summarised by an alert module. A scripted driver replays recorded snapshots and verdicts at $0.

**Tech Stack:** Node 22 ESM `.mjs` with `node --test`, the existing `tests/e2e/lib` (sandbox, checks, report), `eval/lib/cli.mjs` (`claudeJson`, `arg`), Python/pytest in the sandbox.

**Spec:** `docs/superpowers/specs/2026-10-31-journey-e2e-design.md`

## Global Constraints

- Actor model `claude-haiku-5-5`; inspector and reviewer `claude-sonnet-5-5`; coordinator never Opus.
- One inspector launch per stage; rubric files at most 60 lines; subagent briefs at most 60 lines.
- Default spend cap $25 per run, wall-clock budget 60 min; both overridable with `--cap` and `--minutes`.
- Inspector tools: Read, Grep, Glob, Bash limited to `git`, `pytest`, `cat`. A before/after diff of the sandbox must be empty or the stage fails.
- Severity rule: failed deterministic gate and structural rubric items are `block`; judgement items are `warn`. A rubric item missing from the inspector's answer, or `pass`/`fail` without evidence, is a `fail`.
- Stops are detected from state (`sdlc approve` refusal text, `sdlc status --json`), never from prose. At most 3 `--continue` per stage, then violation `stuck-on-input`.
- Approvals: the reviewer decides; the runner sets `SDLC_HUMAN=1` only for that command, in the sandbox only. The scripted negative check that `approve` exits 3 without it stays.
- The suite never fixes anything and never edits `triage.json`. Rig stays disabled on this repo. Plugin loaded with `--plugin-dir`, never user scope.
- `test:e2e:parallel` and `test:e2e:stacks` and their CI steps are left alone. Live runs are started by a person, never CI.
- Verification: run `npm test` and `npm run typecheck` yourself and quote the output.

## Review Focus

- Inspector returns prose, truncated JSON, or an unknown item id: stage fails with violation `inspector-malformed`, never passes.
- Inspector edits a file despite the allowlist: the no-edit guard fails the stage.
- Reviewer approves a chart the deterministic gate blocks: the gate wins, no approval is run.
- `--from J4` on a sandbox whose earlier stages did not pass: refuse with a clear message.
- A violation id already `accept`ed in `triage.json` must not alert or change the exit code; a new one must.
- Spend cap reached mid-journey: remaining stages `not-run`, violation `cap-reached`, report still written.
- Sprint 1 test files for unchanged ACs edited in sprint 2: caught by the byte-identical gate even when `pytest` is green.

**Files:**

### Task 4: Stage table and orchestrator

**Files:**
- Create: `tests/e2e/journey/stages.mjs`, `tests/e2e/journey/journey.mjs`, `tests/e2e/journey/journey.test.mjs`

**Interfaces:**
- Consumes: Tasks 1–3 (`createViolationLog`, `inspect`, `review`, the gates), `Checks`.
- Produces:
  - `STAGES: Stage[]` with `Stage = { id: 'J0'..'J6', title, rubric: string (file basename), perIntent?: boolean, act(ctx), gate(c, ctx), approve?: boolean }`.
  - `runJourney({ sb, driver, inspector, reviewer, log, rubricDir, intents = Infinity, from = 'J0', capUsd, minutes, now }) → Promise<StageResult[]>`, `StageResult = { stage, status: 'pass'|'fail'|'warn'|'not-run', checks: Checks, verdicts: VerdictItem[], costUsd, minutes }`.
  - Behaviour: for each stage in order from `from`: `act` → `gate` → (only if the gate has no failed check) `inspect` → add every `fail`/`warn` item and failed check to `log`. A `block` failure marks later stages `not-run`. For `approve: true` stages the `reviewer` runs first; `reject` adds violations and skips the approve command. `perIntent` stages run once per intent in `sdlc ready --json` order up to `intents`. `from` refuses with `Error('cannot resume at J4: J3 did not pass')` unless `.rig/journey-state.json` in the sandbox says earlier stages passed (the orchestrator writes it).
  - Cap/time: before each act, if `driver.spentUsd() >= capUsd` or elapsed > `minutes`, remaining stages are `not-run` and a `cap-reached` violation is added.
