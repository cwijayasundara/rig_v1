# W3c: measure with rig on, and richer greenfield and brownfield integration tests

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the maintainer decided that rig mode is on once rig is installed (`docs/GOAL.md`). This plan does two things:
- **Task A:** the eval measures two rig arms, and no bare arm.
  - `rig-on`: rig is installed and the session gets plain prompts.
  - `rig-start`: the full workflow.
- **Task B:** the scripted e2e (`npm run e2e:scripted`, $0) proves the always-on promise on greenfield and on a foreign brownfield
  repo. It also exercises the W1 and W2 artefacts that it does not cover today.

**Spec:**
- `docs/GOAL.md` (the rig-mode paragraph).
- `scripts/hooks.ts:152` and `:244` (post-edit and Stop run their sensors with no active change).
- The two vendor bugs the brownfield eval found (commit `023cf93`). No integration test caught them.

## Global Constraints

- **Cost:** everything here is $0. There are no live runs: `npm run e2e` and a non-dry `npm run eval` are the person's to start.
- **Sizes:** each file is at most 500 lines. A new e2e group gets a `FLOOR` entry, as in `tests/e2e/extras.mjs:16`, so lost checks are
  noticed.
- **Fix the harness:** if a new check finds a rig bug, fix it in `scripts/`, `skills/` or `templates/` with a spec that fails without
  the fix. Never weaken the check.
- **Verification:** run the touched specs, `scripts/size.spec.ts`, `scripts/neutrality.spec.ts`, `npm run test:e2e:unit` and
  `npm run e2e:scripted`. The coordinator runs the full suite.

**S7, greenfield with rig on.** On the extras shop after S2/S3, with no active change, the scripted driver makes freeform edits
directly, through the hook entry points the way the scripted driver already drives hooks. Checks:
- A freeform edit that writes a secret, or breaks a blocking sensor, is blocked by the Stop gate with no change active.
- A clean freeform edit passes. `SessionStart` and `UserPromptSubmit` print the "No active change" context and the start nudge.
- The last turn's unfixed warnings are carried into the next prompt.
- **W1:** an Agent launch while a change is active writes a launch row and a done row to `evidence/agents.jsonl`, and the sixth
  counted launch is refused.
- **W2:** with `gates.plan: false`, `S plan-check <slug> --commit` commits the plan, and a contract edit on the change branch blocks.
  `proof` warns on a behaviour proved only by a unit test.
- **W2:** an architecture with an external Integrations row and no stand-in blocks with `arch-standin`.

**S8, brownfield on a foreign repo.** The fixture is a CommonJS package (`"type": "commonjs"`) whose own `npm test` collects test
files recursively. Onboard it the way the brownfield init path does. Checks:
- The vendored checker runs. This is the `.rig/bin/package.json` fix.
- The repo's own `npm test` is still green after onboarding. This is the `.tmpl` fix: confirm the check fails if the slice template
  is vendored without `.tmpl`.
- `CLAUDE.md` maps the existing modules (`assertOnboarding` lane `brownfield`).
- A freeform edit with rig on gets its sensors.
- One scripted `/rig-start` change on the existing code reaches ship, with the existing tests unchanged and frozen.
