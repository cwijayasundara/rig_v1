# W3 (with W0): the trap eval set and the rig arms that measure W1 and W2

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** W0 and W3 of `docs/proposals/2026-11-14-implementation-order.md`. W0 was never built, and W3 runs on it, so this plan has
two parts:
- **W0:** a `traps` eval variant. Each of its traps is a defect that unit tests pass and the running app fails.
- **W3:** the arms that compare rig before W1 with rig after W1+W2, and Haiku-light with Sonnet-light. Each arm is scored on escaped
  defects per dollar.

**Architecture:** `traps` is a new variant built in the same shape as `eval/variants/contract.mjs`.
- **Starting point:** it starts from the built B1–B14 shop.
- **Rig arms** build B15–B18 as four changes (S15–S18).
- **Bare arms** get one prompt for all four behaviours.
- **Hidden checks** run the model's code in child processes, exactly as `contractChecks` does.

**Tech Stack:** Node 22 ESM (`.mjs`), `node:test`, and no new dependencies. In particular there is no Playwright: the UI page is
server-rendered HTML, checked over HTTP. Playwright comes with the React + Vite pack in W6.

**Spec:**
- `docs/proposals/2026-11-14-inner-loop-from-poteto-mode.md` §6 (the traps).
- `docs/proposals/2026-11-14-frontend-design-in-the-loops.md` U0.
- `docs/proposals/2026-11-14-path-to-production-and-adoption.md` Phase 1 (metrics and kill rule).

## Global Constraints

- **Free versus paid:** every live run costs money and is started by a person. This plan builds, and proves only with `--dry` and
  specs. The paid runs come after, once the person has approved the dollar estimate.
- **Dry runs:**
  - A dry run of `traps` scores full marks for both a rig arm and a bare arm, at $0.
  - Each trap's plausible slip is caught by its own check group: the spec takes the reference, breaks one trap, and expects only that
    group to fail.
- **Escaped defect:** counted when a run's `npm test` passed but a trap's hidden check failed. The row carries
  `traps: { route, flag, scale, uiError, uiField }`, each `true` (caught/correct) or `false` (escaped), and `escaped: <count>`.
- **Caps and verification:** all files at most 500 lines. Run only the touched specs plus `scripts/size.spec.ts` and
  `scripts/neutrality.spec.ts`. The coordinator runs `npm test`.

## Review Focus

- **The traps must not be in the prompt.** Each rule lives in a repo document or in existing code, the way
  `docs/api-conventions.md` does for `contract`. The bare prompt and the rig phase prompts name the behaviour and point at the
  document, never at the trap itself. A spec asserts that no prompt string contains the trap words.
- **The scale check must be deterministic on a slow CI machine.** It uses a generous wall-time bound (2 s against about 50 ms for the
  reference), and a naive O(customers × orders) solution must take above 10 s on the seeded data. It is tested in Task 1 with a naive
  fixture.
- **An old plugin ref given in `RIG_EVAL_PLUGIN`** may reject registry keys added since (for example `models` or `proof`). `setupRig`
  sends those keys only when the plugin's `scripts/registry.ts` knows them. This is tested in Task 2.
- **A run that errors** (the session crashed) gives `escaped: null`, not 0, so it can never count as a clean run.
- **Pairing:** two invocations that use the same `--seed` but different `RIG_EVAL_PLUGIN` values put the arms in the same order. Each
  row records `plugin: <sha7>`, so the report can pair them.

**Seed** (committed in the base; this is where the traps live):
- **`src/http/routes.js`** is the only route table. `handler.js` dispatches from it, and a handler that is not registered there gives
  a 404. `docs/api-conventions.md` gains one line saying so.
- **`bin/shop.mjs`** is a CLI with a small hand-written `parseArgs` that accepts only `--flag value`. `docs/cli-conventions.md` says
  every flag accepts both `--flag value` and `--flag=value`, and that an unknown flag exits 2 with `unknown flag: --x` on stderr.
- **The orders store** has a loader. The hidden scale check uses it to load 100 000 orders across 10 000 customers.
- **`docs/ui-conventions.md`** says three things:
  - every page renders an error state (`<p role="alert">…</p>`, with HTTP status 503) when the store throws;
  - an empty list renders `<p>No orders yet</p>`;
  - a page renders only fields that `api/openapi.yaml` declares, and a missing field is added to the contract first.

**Behaviours** (brief lines, phase prompts and tests, each naming only the behaviour and its document):

| B | Behaviour | Trap (hidden check, child process, against the running server or the CLI) |
|---|---|---|
| B15 | `GET /orders/<id>/receipt` returns the receipt text | `route`: HTTP 200 from the real server. The trap is a handler written and unit-tested but never added to `routes.js` |
| B16 | `node bin/shop.mjs export --since <date> --format csv` | `flag`: `--format=csv` and `--since=2026-01-01` work, and `--bogus` exits 2 |
| B17 | `GET /reports/top-customers?limit=N` by total spend | `scale`: correct top 10 on the 100k seed in under 2 s |
| B18 | `GET /orders/view`: an HTML page listing id, customer, total and **status label** | `uiError`: the page gives 503 with `role="alert"` when the store throws. `uiField`: every rendered column is in `openapi.yaml` (the status label is not in the seed contract, so a correct run adds it) |

  - `dryOverlay(sb)`;

**Interfaces:**
- **`PLUGIN`** becomes `path.resolve(process.env.RIG_EVAL_PLUGIN || <repo root>)`. The row gains `plugin`, the short sha of `PLUGIN`'s
  HEAD (`null` when it is not a git checkout). An old ref is checked out by the person with `git worktree add ../rig-pre-w1 7324485`
  (the first parent of the W1 merge).
- **New arms:**

  | Arm | Model | rig | policy | Registry `models.light` |
  |---|---|---|---|---|
  | `sonnet-rig` | sonnet | true | continuous | default |
  | `sonnet-rig-light-haiku` | sonnet | true | continuous | `{build:'haiku',evaluate:'sonnet'}` (the D1 default) |
  | `sonnet-rig-light-sonnet` | sonnet | true | continuous | `{build:'sonnet',evaluate:'opus'}` |

  `setupRig` merges `arm.models` into `registry.models`, but only when
  `fs.readFileSync(path.join(PLUGIN,'scripts/registry.ts'),'utf8').includes("'models'")`. Otherwise it drops the key and records
  `row.modelsIgnored = true`.
- **Report:** a column `escaped` (the sum, over runs with a non-null `escaped`) and a column `$/escaped-free run`. The rows are grouped
  by `arm@plugin` when more than one plugin is present.

### After the plan: the paid runs (the person starts them)

1. **W0 exit:** `--variant traps --arms sonnet-bare,haiku-bare --runs 3`. At least 2 traps must escape the bare arms. If fewer escape,
   write harder traps before spending anything on rig arms.
2. **W3 run 1, rig before and after W1+W2:** `--arms sonnet-rig --runs 3 --seed S`, run twice, once with
   `RIG_EVAL_PLUGIN=../rig-pre-w1` and once without.

4. **Report:** `node eval/report.mjs <results>`. It gives escaped defects per dollar for each arm, and the verdict goes into
   `docs/proposals/2026-11-14-implementation-order.md`.
