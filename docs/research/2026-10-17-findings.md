# Research findings: a thin production harness for Claude Code

Date: 2026-10-17. Goal: `docs/GOAL.md`. Raw agent notes: `docs/research/raw/2026-10-17-*.md`.

**Confidence.** The four notes were written by subagents from WebFetch summaries and search snippets, not full-page reads. Treat
every number below as a lead until re-fetched. The claims the spec will lean on are listed under "To verify before the spec".

## 1. What the sources say

**Fowler / Böckeler / Jain** (harness-engineering, sensors-for-coding-agents, are-harnesses-worth-the-cost)
- A harness is everything except the model. Guides steer before, sensors observe after; computational ones are fast and
  deterministic, inferential ones (LLM review) cost more and are probabilistic.
- The steering loop: when an issue recurs, a human improves the guide or sensor. Cadence follows "keep quality left".
- Cost study: two OpenAI models, one Java service, 10 paired runs, 178 hidden checks. Strong model: 10/10 with and without the
  harness, 7x the dollars. Cheap model: 3/10 to 10/10, still cheaper than bare strong. No Claude model was measured.
  Final-gate-only for strong models was proposed, not tested.
- Warnings: feedback overload, coverage is not effectiveness, mutation testing is costly, and telling the agent to run sensors in
  AGENTS.md is unreliable, so use hooks.
- **Silent on:** PRD decomposition, test plans, memory, wiki, how to delete guides. Silence is not evidence against them.

**Devin**
- Memory: markdown in git, `MEMORY.md` index loaded each session, one-line entries with source and date, a roughly daily
  "dreaming" pass that merges and prunes. Personal to a user; no documented validation of lessons.
- DeepWiki: a steered page plan (`.devin/wiki.json`, 30 pages), manual regeneration, no published accuracy numbers.
- Playbooks: procedure, postconditions, forbidden actions. Large work is split into file-disjoint packages by a coordinator.
  No first-class intents or test-plan objects.
- Cognition's own stance: single-threaded writes, read-only helpers, a clean-context reviewer.

**Others**
- Light and well liked: Anthropic's long-running pattern (JSON feature list, progress file, git, one feature per session), Kiro and
  OpenSpec specs, human-written AGENTS.md (an ETH Zurich study reports auto-generated ones lowered success and raised cost 20%+).
- Heavy: Spec Kit, BMAD, planner/generator/evaluator agent trios.
- Learning from failures: Cursor Bugbot reports 52% to 78% with learned rules that are promoted and demoted (vendor metric).
  Full rewrites of memory cause context collapse; delta edits avoid it. Bad lessons can spread.
- Nobody found with a machine-checked requirement-to-task-to-test chain, and no published lift for wiki, memory or spec tools.
- Scaffold choice moves scores about 10 points and tokens per solved task by up to 40x (one preprint). "A harness helps cheap
  models more" rests on Jain's single study.

## 2. What native Claude Code already covers (fall back to these)

Full or near-full native coverage, so rig should not own it:
- **Guide injection:** `.claude/rules/*.md` with `paths:` frontmatter. Generate rules from the registry; delete the injection code.
- **Review:** `/code-review` (effort levels, `--comment`, `--fix`) plus a `REVIEW.md`. The `evaluator` agent is the only rig piece
  with a case to stay, for review against the spec, plan and contracts.
- **Model recording:** `PostModelSwitch` and `PostToolUse` on `Agent` (`resolvedModel`, `modelsUsed`). One hook, not two.
- **Per-edit type feedback:** LSP plugins.
- **Long unattended runs:** `/goal`, routines, `/loop`, `claude -p`.
- **Cost and context policy:** settings only (`CLAUDE_CODE_SUBAGENT_MODEL`, `--max-budget-usd`, `autoCompactWindow`).
- **Plugin-level evals:** `claude plugin eval` with with/without ablation and a `--threshold` exit code (early access).

No native equivalent, so rig keeps or rebuilds these:
- Git-level hooks that judge any editor, and a CI gate judged by the **base branch's** checker.
- Content-aware test-tamper detection, frozen contracts, hash-and-staleness approvals, spec-to-test traceability with red-proof.
- **The whole outer loop:** PRD to intents with dependencies, architecture and ADRs, test plan, cases and data. Native offers
  `/batch` (mechanical fan-out), dynamic workflows and Projects (beta, Pro/Max only).
- **Code wiki:** nothing native beyond LSP navigation and nested CLAUDE.md.
- **Memory:** native auto memory is local, uncommitted and has no consolidation pass or promotion to a mechanical rule.

## 3. Consequences for the goal

1. **Thin means: shrink what native now covers, keep what it does not.** The cheapest wins are generated `.claude/rules`, `/code-review`
   with `REVIEW.md`, and one model-recording hook.
2. **The outer loop is the largest gap with no native answer and no competitor doing the traced version.** It stays in scope. Build it
   as skills plus one deterministic trace script, on the new registry and behaviour IDs (FR/NFR to B-number to sensor), not as the
   old chart state machine. Reuse the model-by-role split: Opus architect for architecture and decomposition, Sonnet for the test plan.
3. **Wiki and dream are unproven by everyone, including Devin.** Do not rebuild them first. The old `evals/wiki-search.json`
   and `evals/memory-recall.json` should be run against native auto memory plus LSP. Rebuild only what shows lift.
4. **Learning loop design, if kept:** committed markdown, one-line entries with provenance, delta edits only, candidates reviewed by
   a human, demotion when a lesson stops firing, and promotion of a recurring lesson to a `rules.json` sensor (the Fowler
   steering loop, automated up to the approval step). Our old module had validation and daily caps that Devin's lacks.
5. **Measurement is the gate.** Every kept part needs an arm in `eval/`. Use cost per accepted task with enough runs. A part with no
   lift after two passes is cut (spec §9 rule). Sprint-level parts need their own measure (trace coverage, rework per intent),
   since the shop brief cannot score them.
