# What native Claude Code already provides, and what rig must still own

Date of research: 2026-10-17. Source: https://code.claude.com/docs/en/* (fetched through WebFetch, which summarises; large pages were read in chunks or grepped from saved copies). Latest "What's new" page indexed is Week 37 (Sep 7-11, 2026, v2.1.263-269); changelog went to at least v2.1.299 (referenced in scheduled-tasks). Repo read: README, DESIGN, hooks.json, 9 skills, evaluator agent, scripts headers, templates, `brain/README.md` at 72c8988^, `chart` skill at 4244194^.

## 1. Native inventory (facts to build on)

Doc base: `https://code.claude.com/docs/en/<slug>`.

- **Plan mode** (`permission-modes`): `plan` mode = read-only research, then a plan the person approves; Shift+Tab, `/plan <prompt>`, `--permission-mode plan`, `permissions.defaultMode: "plan"`. Approving exits plan mode and picks the next mode. Plan files live in `~/.claude/plans/` or `plansDirectory` (settings). `opusplan` alias = Opus in plan, Sonnet to execute (`model-config`). Approval is a session event: no hash, no staleness, nothing committed.
- **Permission modes**: `default` (shown as Manual), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`. **Auto mode** = a separate classifier model reviews actions; it is the built-in start mode from v2.1.283 for interactive terminal/VS Code; admin switch `permissions.disableAutoMode: "disable"`; tuning at `auto-mode-config`; `PermissionDenied` hook event. Project `.claude/settings.json` cannot set `auto` or `bypassPermissions` as `defaultMode`.
- **Memory** (`memory`): CLAUDE.md (managed, user, project, `CLAUDE.local.md`), `@path` imports (max 4 hops), `.claude/rules/*.md` with `paths:` frontmatter (loads only when matching files are touched), `claudeMdExcludes`, `AGENTS.md` read when no CLAUDE.md (v2.1.277+), `/init`, `/memory`. **Auto memory**: on by default, `~/.claude/projects/<project>/memory/` with `MEMORY.md` index (first 200 lines/25 KB loaded) plus topic files typed `user|feedback|project|reference`; machine-local, shared across worktrees, excluded from the retention sweep; `autoMemoryEnabled`, `autoMemoryDirectory`, `CLAUDE_CODE_DISABLE_AUTO_MEMORY`. Subagents can have `memory: user|project|local`. No consolidation ("dream") pass is documented.
- **Skills** (`skills`): frontmatter `name, description, when_to_use, arguments, disable-model-invocation, user-invocable, allowed-tools, disallowed-tools, model, effort, context: fork, agent, background, hooks, paths, shell`; `` !`cmd` `` dynamic injection; limits 500 lines, 1,536 chars of description; bundled skills `/code-review /batch /debug /loop /verify /run /skill-doctor /workflow-authoring /simplify /security-review`.
- **Subagents** (`sub-agents`): frontmatter `tools, disallowedTools, model (sonnet|opus|haiku|fable|id|inherit), permissionMode, maxTurns, skills, mcpServers, hooks, memory, background, isolation: worktree, effort, omitClaudeMd, autoCompactWindow`. Plugin agents ignore `hooks`, `mcpServers`, `permissionMode`. Model order: per-call `model`, frontmatter, `CLAUDE_CODE_SUBAGENT_MODEL`, parent model; `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` forces one. Limits: depth 3, 20 concurrent. Built-ins: Explore, Plan, general-purpose, claude, statusline-setup, claude-code-guide.
- **Agent teams** (`agent-teams`): experimental, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`; lead + teammates + shared task list + mailbox; hooks `TeammateIdle`, `TaskCreated`, `TaskCompleted` (exit 2 blocks). Not in `-p`. **Dynamic workflows** (`workflows`): a JS script (`agent()`, `pipeline()`, `parallel()`, `phase()`) run by a runtime, resumable, up to 16 concurrent / 1,000 agents; `/workflows`, `ultracode` keyword, `/effort ultracode`, saved in `.claude/workflows/`, shipped in plugins (`workflows/`), bundled `/deep-research`; org switch `disableWorkflows`.
- **Hooks** (`hooks`, `hooks-guide`): 33 events: SessionStart, Setup, UserPromptSubmit, UserPromptExpansion, PreToolUse, PermissionRequest, PermissionDenied, PostToolUse, PostToolUseFailure, PostToolBatch, Notification, MessageDisplay, SubagentStart/Stop, TaskCreated/Completed, Stop, StopFailure, TeammateIdle, InstructionsLoaded, ConfigChange, CwdChanged, DirectoryAdded, FileChanged, WorktreeCreate/Remove, PreCompact/PostCompact, **PreModelSwitch, PostModelSwitch**, Elicitation, ElicitationResult, SessionEnd. Handler types: `command` (with `args` exec form, `async`, `shell`, `onFailure`), `http`, `mcp_tool`, `prompt` (single-turn LLM, returns `{ok, reason}`, 30 s), `agent` (multi-turn with tools, up to 50 turns, 60 s, **experimental**). Common input: `session_id, prompt_id, transcript_path, cwd, permission_mode, effort{level}, hook_event_name, agent_id/agent_type`. Exit 0 = ok (stdout JSON parsed), **2 = block** (PreToolUse, UserPromptSubmit, PreCompact, PreModelSwitch, ConfigChange, TaskCreated/Completed; on Stop/SubagentStop/TeammateIdle it keeps Claude working), other = non-blocking. JSON: `decision:"block"`, `hookSpecificOutput.permissionDecision` allow|deny|ask|defer, `updatedInput`, `updatedToolOutput` (PostToolUse), `additionalContext` (10,000 char cap). Stop hook continuation cap 8 (`CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`). `if:` field filters by permission-rule syntax. Hook timeouts default 600 s (30 s on UserPromptSubmit/model-switch hooks).
  - **Model name in hook input**: not a common field. `SessionStart` may carry `model` (docs say "may be absent"). `PreModelSwitch`/`PostModelSwitch` carry `from_model`, `to_model` (and `context_tokens`, `estimated_cache_write_usd`, `pricing`). For subagents: PreToolUse on `Agent` has optional `tool_input.model`; PostToolUse `tool_response.resolvedModel` and `modelsUsed` (v2.1.212+) give the model the subagent really ran on. Status line JSON has `model.id`, `model.display_name`. OTel `api_request` events carry `model`. No `$CLAUDE_MODEL`; `ANTHROPIC_MODEL` is not updated by `/model`.
- **Plugins and marketplaces** (`plugins-reference`/`manifest-reference`, `plugins/create-marketplace`): components `skills/ agents/ commands/ hooks/hooks.json .mcp.json .lsp.json output-styles/ workflows/ themes/ monitors/ bin/ settings.json`; `userConfig`, `dependencies`, `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`; `claude plugin validate`; marketplace.json with `github|git-subdir|url|npm|archive|command` sources; team enablement via `enabledPlugins` + `extraKnownMarketplaces`; `--plugin-dir`. A root CLAUDE.md in a plugin is NOT loaded. Plugin `settings.json` only honours `agent` and `subagentStatusLine`. `claude plugin eval` (v2.1.269, `plugin-evals`).
- **Managed settings** (`managed-settings`, `server-managed-settings`): `/Library/Application Support/ClaudeCode/managed-settings.json` (mac), `/etc/claude-code/` (Linux/WSL), `C:\Program Files\ClaudeCode\`; `managed-settings.d/*.json`; macOS plist domain `com.anthropic.claudecode`; Windows HKLM; claude.ai admin console (server-managed). Keys: `allowManagedHooksOnly`, `allowManagedPermissionRulesOnly`, `allowManagedMcpServersOnly`, `strictKnownMarketplaces`, `blockedMarketplaces`, `availableModels`/`deniedModels`/`enforceAvailableModels`, `disableAutoMode`, `disableBypassPermissionsMode`, `forceRemoteSettingsRefresh`, `requiredMinimumVersion`, `modelPricing`, `disableWorkflows`, sandbox locks. Precedence: managed > `--settings` > local > project > user.
- **Sandbox** (`sandboxing`): OS-enforced (macOS Seatbelt, Linux/WSL2 bubblewrap) filesystem and network limits for Bash/PowerShell/Monitor; file tools, MCP and hooks run outside it.
- **Worktrees** (`worktrees`): `claude -w <name>` (also `#PR`), `EnterWorktree/ExitWorktree` tools, subagent `isolation: worktree`, `.worktreeinclude`, `worktree.baseRef`, isolation checks that block edits/git into the main checkout, `WorktreeCreate/Remove` hooks for non-git VCS.
- **Checkpoints** (`checkpointing`): per-prompt file snapshots (last 100), `/rewind` or Esc Esc; restore code/conversation/both, "summarize from here". Does NOT track Bash edits or most subagent edits. Not a substitute for git.
- **Headless / SDK** (`headless`, `agent-sdk/*`): `claude -p`, `--output-format text|json|stream-json`, `--json-schema`, `--bare`, `--allowedTools`, `--permission-mode`, `--permission-prompts none`, `--max-turns`, `--max-budget-usd`, `--resume`, `--append-system-prompt`; JSON result has `total_cost_usd` and per-model cost, `permission_denials`; `system/init` lists plugins, `plugin_errors`, `mcp_server_errors`. Python/TS SDK exposes hooks, subagents, MCP, permissions, sessions, plugins, cost tracking, OTel.
- **CI** (`github-actions`, `gitlab-ci-cd`): `anthropics/claude-code-action@v1` with `prompt`, `claude_args`, `plugin_marketplaces`, `plugins`, `settings`; interactive `@claude` and automation mode; runs skills (`/code-review:code-review --comment ...`); `/install-github-app`; OIDC federation; workflow tokens do not trigger CI on their own commits. GitLab CI/CD has a parallel page.
- **Review**: local `/code-review` (alias `/review`; effort low..max, `--fix`, `--comment`, `--max-findings`, target = PR/branch/path/range, runs as a background forked subagent, follows CLAUDE.md, not REVIEW.md); `/code-review ultra` = cloud ultrareview (`ultrareview`; `claude ultrareview` subcommand for CI); managed **Code Review** (`code-review`; Team/Enterprise, GitHub only; multi-agent + verification; `REVIEW.md` customisation; check run named "Claude Code Review", never approves or blocks; Quick/Standard/Deep levels); `/security-review` (current branch); `security-guidance` plugin (hook-based: per-edit pattern check, Stop diff review, commit/push review; extra rules via `.claude/claude-security-guidance.md` and `security-patterns.yaml`); `claude-security` plugin (multi-agent repo scan).
- **Scheduling / long-running**: `/loop` (session-scoped cron, 7-day expiry, `CronCreate/List/Delete`, `loop.md`), **Routines** (`routines`, research preview: cloud, schedule/API/GitHub-event triggers, `/schedule`), Desktop scheduled tasks, **`/goal`** (`goal`: a session-scoped prompt-based Stop hook; a small fast model judges the completion condition each turn; condition up to 4,000 chars; works in `-p`; unavailable if `disableAllHooks` or `allowManagedHooksOnly`), background agents / agent view (`agent-view`), Monitor tool, `ScheduleWakeup`, `claude --cloud`/teleport, Remote Control, Channels.
- **MCP** (`mcp`): scopes local/project/user, `.mcp.json`, http/sse/stdio/ws, OAuth, tool search (deferred tool definitions), `claude mcp serve`, `managed-mcp.json`, `managedMcpServers`, elicitation hooks. Jira/GitHub/Sentry/Notion are MCP examples. There is NO first-party issue-tracker or PRD feature.
- **Output styles** (`output-styles`): Default, Proactive, Concise, Explanatory, Learning; custom `.claude/output-styles/*.md` (`keep-coding-instructions`, `force-for-plugin`); setting `outputStyle`. Instruction-only, no enforcement. **Status line** (`statusline`): `statusLine` setting runs a script with JSON on stdin (`model.id/display_name`, `cost.total_cost_usd`, `context_window`, `session_id`, `prompt_cache`, rate limits).
- **LSP / code intelligence** (`plugins/code-intelligence`): LSP plugins for 13 languages (TS, Python, Go, Rust, Java, C/C++, C#, Kotlin, Swift, Ruby, PHP, Lua, Liquid); after each edit Claude gets "Found N new diagnostic issues" (type errors, missing imports) plus an `LSP` navigation tool. Terminal sessions only, not cloud.
- **Models and effort** (`model-config`): aliases `default best fable sonnet opus haiku sonnet[1m] opus[1m] opusplan`; `/model`, `--model`, `ANTHROPIC_MODEL`, `model` setting; `availableModels`; effort `low|medium|high|xhigh|max` + `ultracode`; `/effort`, `maxEffortLevel`, per-model effort in `modelSettings`; `--fallback-model`. Advisor tool exists (`advisor`).
- **Cost and telemetry** (`costs`, `monitoring-usage`, `analytics`): `/usage` (session cost per model, prompt-cache line, plan attribution to skills/subagents/plugins/MCP, loops), `/cost` is referenced for the cache line, `/insights`, `/skill-doctor`; OpenTelemetry via `CLAUDE_CODE_ENABLE_TELEMETRY=1` and `OTEL_*`: metrics `claude_code.cost.usage, token.usage, session.count, commit.count, pull_request.count, lines_of_code.count, code_edit_tool.decision`, events `api_request` (model, cost_usd), `tool_decision`, `tool_result`, `user_prompt`, `skill_activated`, `plugin_loaded`; managed-settings can pin the collector. Team/Enterprise analytics dashboard (adoption, "PRs with CC", PRs labelled `claude-code-assisted`), Console dashboard, Claude Code Analytics API, Enterprise Analytics API.
- **Projects** (`claude-projects`): public beta, Pro/Max only (not Team/Enterprise), cloud threads coordinated by Claude for a stream of related work.

## 3. Native features that make rig features redundant (candidates for removal or replacement)

1. **Path-scoped guides** -> `.claude/rules/*.md` with `paths:` (and skill `paths:`). Native and loaded without hook code.
2. **Evaluator agent** -> `/code-review` (local, effort levels, `--comment`) and the managed Code Review service; `REVIEW.md` already shipped in templates.
3. **Model recording** -> `PostModelSwitch`, `resolvedModel`/`modelsUsed` in PostToolUse(Agent), OTel `api_request.model`. rig's `modelstate.ts` mostly mirrors these.
4. **Type/lint feedback after each edit** -> LSP plugins (live diagnostics) for 13 languages; rig's per-language edit-cadence command sensors overlap.
5. **Security review in session** -> `security-guidance` plugin (3 layers) and `/security-review`.
6. **Auto memory** -> covers the simplest "learn from corrections" use of the removed dream memory; machine-local and uncommitted though.
7. **`/goal`, routines, `/loop`** -> any bespoke continue/loop skill or the wait-polling cited in DESIGN section 1.
8. **Plugin evals (`claude plugin eval`, v2.1.269, early access)** -> the per-part "does it lift a model" measurement (GOAL scope item 5) for skills, agents and hooks of a plugin.
9. **Dynamic workflows (`workflows`, `/batch`)** -> any custom fan-out for PRD decomposition or SDD loop; subagent-driven development in superpowers.
10. **`TaskCreated`/`TaskCompleted` hooks + task list** -> native place to gate "task done only if test exists" without custom state.

## 4. What native does NOT give (rig must keep, thinly)

- Persistent human approval that records hashes and goes stale (native plan approval evaporates with the session).
- Frozen contracts and the frozen-file finding.
- Git-level enforcement for any editor; CI that re-judges with the base branch's checker.
- Spec behaviours -> tests traceability and red-proof.
- Everything in the outer loop: PRD -> intents, architecture/ADRs, test plan/cases/data (all three have no native feature, no issue-tracker integration other than generic MCP).
- Code wiki (nothing native).
- Reviewed, committed, promoted lessons (native auto memory is local and unreviewed).

## 6. Suggested thin architecture (for the spec that follows)

1. **Keep as the irreducible core** (about 6 scripts): `approve/waive` human gate + hash/staleness, `contracts` freeze, `verify` (traceability, red-proof, stamp), `pr`, one `check` entry point shared by Stop, git hooks and CI, `rig-check.yml`.
2. **Hand to native**: guides -> `.claude/rules` with `paths:`; review -> `/code-review` + `REVIEW.md`; model record -> `PostToolUse(Agent).resolvedModel` + `PostModelSwitch`; type feedback -> LSP plugins; long runs -> `/goal`; evals of skills -> `claude plugin eval`; memory -> native auto memory (plus `/rig:rule` for promotion only).
3. **New outer-loop pieces as skills/workflows, not hooks**: `chart` (PRD -> intents + deps, architecture/ADRs, test plan/cases/data) with a deterministic trace check and a single human approval; MCP tools to push intents to Jira/Linear/GitHub issues.
