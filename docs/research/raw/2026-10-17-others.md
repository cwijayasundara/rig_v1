# How others solve the same problems (survey for a thin Claude Code harness)

Date: 2026-10-17. Method: WebSearch only (about 12 queries). I did NOT open most primary pages with WebFetch; many facts come from search-result summaries and third-party write-ups. Tags: [documented] = stated in a source I saw (primary or secondary, noted); [inferred] = my reasoning. Treat numbers as "as reported", not verified. Several sources are 2026 preprints, some revised after publication.

## A. Harnesses and guardrails around coding agents

1. Anthropic, "Effective harnesses for long-running agents" (Nov 2025). https://www.anthropic.com/engineering (summarised via secondary posts, e.g. https://dev.to/claudiuspapirus/why-ai-agents-fail-long-projects-and-the-anthropic-fix-3029)
   - Initializer agent writes init.sh, claude-progress.txt, feature_list.json (each feature passing/failing) and a first git commit; each later session picks ONE failing feature, tests it end to end (Puppeteer MCP), commits. Open-sourced in anthropics/claude-quickstarts with a bash allowlist. [documented, secondary]
   - Failure modes targeted: declaring victory early, marking features done untested, leaving broken state. [documented]
   - Anthropic says harness assumptions go stale: context resets needed for Sonnet 4.5 were unneeded with Opus 4.5. [documented, secondary]
   - Weight: light (3 files + git). Copy: JSON feature list with pass/fail, one-feature-per-session, git as handoff. Avoid: keeping scaffolding the next model no longer needs.
2. Anthropic, "Harness design for long-running application development" (planner/generator/evaluator, 2026). https://www.anthropic.com/engineering/harness-design-long-running-apps ; InfoQ https://infoq.com/news/2026/04/anthropic-three-agent-harness-ai/
   - Evaluator drives the running app with Playwright and fails sprints below threshold. Secondary sources say solo run $9 / 20 min was broken vs about $200 for the 3-agent harness with a polished result. I could not confirm those figures against the post. [documented, unverified numbers]
   - Weight: heavy (20x cost). Copy: a separate skeptical evaluator that exercises the running thing. Avoid: using it for small changes.
3. OpenAI, "Harness engineering: leveraging Codex in an agent-first world" (Feb 11 2026). https://openai.com/index/harness-engineering/
   - Team built about 1M lines in about 5 months with zero hand-written code; claims about 1/10 the hand-coding time. "Humans steer, agents execute"; investment goes into environment, intent specs, feedback loops, repo "legibility". AGENTS.md was itself generated then curated. [documented; vendor self-report, no control group]
4. Cursor Bugbot. https://cursor.com/blog/building-bugbot ; https://cursor.com/changelog/04-08-26
   - Resolution rate (AI judge checks at merge whether flagged bugs were fixed) went 52% to over 70% across 40 experiments, then 78% after "learned rules" (candidate rules from reactions/replies/review comments; promoted if they gain signal, disabled if not). Cursor's own metric; its comparison against Greptile 63%, CodeRabbit 49%, Copilot 47% is vendor-run. [documented, vendor]
   - Copy: rules are candidates with a measured promote/demote lifecycle. Avoid: trusting vendor-run comparisons.
5. Repo-level context files. "Evaluating AGENTS.md" (ETH Zurich, arXiv 2602.11988, ICLR 2026). https://iclr.cc/virtual/2026/10021142
   - LLM-generated context files lowered success slightly (about -0.5pt SWE-bench Lite, -2 to -3pt AgentBench); human-written ones gave about +4pt on AgentBench; both raised cost 20%+ via more exploration. Authors: keep only minimal requirements. Details vary across secondary reports; I did not open the paper. [documented, secondary]
   - Strong implication for a thin harness: every line of CLAUDE.md/rules has a cost. Avoid auto-generated context files.
6. Superpowers plugin (obra). Evidence is anecdotal: a 12-session self-test reported about 9% lower cost, 14% fewer tokens (more on simple tasks); a Codex 500-task test (June 2026, secondary) reported accuracy within noise (45.6% vs 47.8%) with +40% tokens. https://www.mejba.me/blog/superpowers-plugin-claude-code-review ; https://pub.towardsai.net/what-is-superpowers-where-it-is-a-must-and-where-it-is-not-8c540af07ffa [documented, weak]. No independent benchmark found. claude-flow, Factory, Cline memory bank, Amp, OpenHands, SWE-agent: searches returned nothing usable; I could not find evidence. Not surveyed further.

## B. PRD/spec to work items, ADRs, test plan

Comparison pages (all vendor blogs/opinion): https://ssojet.com/blog/best-spec-driven-development-tools ; https://developertoolkit.ai/en/ecosystem/frameworks/spec-driven-frameworks/ ; https://codemyspec.com/blog/spec-kit-vs-kiro
- GitHub Spec Kit: gated specify -> plan -> tasks -> implement, 30+ agents, MIT. Reviewers call it heavy (review overload from branch-per-spec). [documented, secondary]
- Kiro (AWS IDE): three markdown files per spec in .kiro/specs/ (requirements in EARS notation with acceptance criteria, design, tasks); bugfix specs generate three test groups (bug exists / fix works / unchanged behaviour holds); "quick spec" mode. Lock-in to the IDE. Source is one third-party guide (https://www.verdent.ai/guides/agents/kiro-spec-driven-development); I found NO evidence on how criteria link to tasks/tests. [documented, single secondary source]
- OpenSpec: change-centric; archiving a change merges it into a living spec; claims lower token use from community benchmarks (unverified). Good for brownfield. [documented, secondary]
- BMAD-METHOD: persona agents (PO, architect, dev, reviewer); heavy, suited to large greenfield. [documented, secondary]
- Taskmaster-AI (claude-task-master): `parse-prd` -> tasks.json, `analyze-complexity` (1-10 threshold) -> `expand` into subtasks, add/validate/fix-dependencies commands. https://docs.task-master.dev/command-reference . Gives requirement -> task with dependency validation; no test linkage found. [documented]
- Linear/Jira integrations, Devin playbooks: not searched; no evidence gathered.
- Traceability finding: none of the sources I saw show requirement -> task -> test as a machine-checked chain; Kiro's EARS criteria is the nearest. [inferred from absence; may be my search gap]
- Lightweight to heavy: Kiro quick-spec / OpenSpec < Taskmaster < Spec Kit < BMAD.
- No measured lift from any spec-driven tool found; adoption/stars only. [documented absence]

## C. Code wiki / indexing

- Claude Code: early versions used a local vector index (Voyager embeddings); team switched to agentic search (grep/glob/read). Boris Cherny called the evidence "internal vibes", with some internal benchmarks. Stated reasons (secondary): simplicity, no staleness, security/privacy. https://officechai.com/ai/claude-researcher-explains-how-agentic-search-performed-better-than-rag-for-code-generation/ ; https://smartscope.blog/en/ai-development/practices/rag-debate-agentic-search-code-exploration/ [documented, secondary]. No published controlled grep-vs-embedding benchmark found.
- Aider repo map: tree-sitter symbol graph + personalised PageRank, rendered into a token budget (default about 1,024 tokens), binary-searched. Third-party descriptions; no lift measurement found. https://www.agentpatterns.ai/context-engineering/repository-map-pattern/ [documented]
- DeepWiki (Cognition) and open clone deepwiki-open (AsyncFuncAI): generated wiki + RAG Q&A; 30k+ repos reported indexed. No independent accuracy benchmark; an OpenWrt maintainer reports hallucinations, no regeneration on update. https://forum.openwrt.org/t/important-consideration-deepwiki-ai-generated-docs-may-contain-inaccuracies/249471 [documented, anecdotal]
- Sourcegraph: search returned nothing; no evidence.
- Databricks benchmarked agents on a multi-million-line codebase (https://databricks.com/blog/benchmarking-coding-agents-databricks-multi-million-line-codebase); I saw only summary numbers on cost, not index effects.
- When an index pays off: [inferred] huge repos, concept search, non-code knowledge (one analysis argues this; unmeasured). For repos that fit agentic search, a generated wiki adds staleness risk with no shown lift.

## D. Self-improvement, memory, rule learning

- Cognition "Memory and Dreaming" (Oct 5 2026) and Agent Memory Repo spec. https://devin.ai/blog/memory-and-dreaming ; https://cognition.com/agent-memory-repo ; https://github.com/AgentMemoryRepo/agentmemoryrepo
  - Memory = git repo of markdown notes; MEMORY.md loaded at session start; each memory links to the session where it was learned (provenance); nightly "dreaming" removes stale records. I did not open the pages; no lift numbers seen. [documented, from search summary]
- Claude Code auto memory / "Auto Dream": background sub-agent dedups, drops stale notes, absolutises dates, keeps MEMORY.md under about 200 lines; trigger about 24h + 5 sessions. Only third-party descriptions; no official doc confirming found. https://claudefa.st/blog/guide/mechanics/auto-dream [documented, secondary, status unclear]
- ACE (Agentic Context Engineering, arXiv 2510.04618, ICLR 2026). Warns of brevity bias and context collapse (a context fell from 18,282 to 122 tokens in one rewrite; accuracy 57.1 vs 63.7 baseline). Fix: generation/reflection/curation with small incremental delta edits, never full rewrites. Claims +10.6% agent benchmarks, +8.6% finance (earlier version said 9.0%). https://arxiv.org/pdf/2510.04618 [documented]
- Cursor Bugbot learned rules (see A4): promote/disable by signal.
- Community: devin-brain (provenance, versioning, quarantine gate) and devin-learning (learnings -> reviewable SKILL.md drafts). Unofficial. https://github.com/Icaro0310/devin-brain [documented]
- Risks, a cluster of 2026 preprints: experience-following spreads bad lessons (OEP, arXiv 2605.18930, >50% attack success on GPT-4o agents); a confabulated rule in a shared rule library entrenches everywhere (arXiv 2605.29463); coding agents re-author poisoned skills (EVOMAL 2608.25776, 11.1%); error-free steps get treated as validated (2606.04329). Mostly adversarial settings; unclear how it transfers to a single-team harness. [documented, preprints; inferred relevance]
- Safeguards seen: provenance link per lesson; quarantine/human review before promotion; incremental delta edits; size caps; demotion on negative signal; staleness removal.

## E. Measuring harness value

- Same model, different scaffold moves scores a lot: Opus 4.5 45.9% (SWE-agent) vs 55.4% (Claude Code) on SWE-bench Pro (arXiv 2605.23950); up to 15 pts for Kimi K2 on Verified (2606.17799). Observational. [documented]
- "Scaffold Effect in Coding Agents" (arXiv 2607.22585): harness shifts tokens per solved task up to 40x; model upgrade only 1.0-1.3x; pass-rate effects within noise at n=50. "Harness or Model?" (2609.11987): neutral harness cost 1.3-1.6x per solved task on Opus 4.8, 1.2x on GPT-5.5 (cost telemetry was revised). [documented, preprints]
- Databricks: Sonnet 5 was 1.7x cheaper per token but cost slightly more per task ($2.09 vs $1.94), 6 points lower completion; same model via two harnesses differed >2x in cost per task. [documented, summary]
- "Harness helps cheap models more": NOT demonstrated. Only anecdote (Confucius agent: Sonnet 4.5 52.7% vs Opus 4.5 52.0% on Anthropic scaffold, https://particula.tech/blog/agent-scaffolding-beats-model-upgrades-swe-bench). One training study points the other way. I found no controlled multi-tier ablation. [documented absence]
- Coding agents have converged on leaderboards; top entries not orderable (arXiv 2609.17394). [documented]
- Superpowers: see A6, noise-level accuracy effects.

## Ranked: ideas worth copying into a thin harness

1. Measure cost per accepted task, not pass rate alone, and compare harness on/off with n large enough to beat noise. Source: 2607.22585, Databricks. Both show cost swings dwarf pass-rate swings and small n hides everything. [documented]
2. Keep always-loaded context minimal; only human-curated, non-inferable requirements. Source: ETH AGENTS.md study. [documented]
3. Durable external state for long work: JSON feature list with pass/fail, progress file, git commits, one item per session. Source: Anthropic long-running harness. [documented]
4. Separate verifier that runs the real thing (tests/browser), used only on bigger changes. Source: Anthropic planner/generator/evaluator; cost caveat. [documented]
5. Lessons as candidates, each with provenance (session/commit link), human or measured promotion, demotion on negative signal, size cap, delta edits only. Sources: Cursor Bugbot, Cognition memory repo, ACE, devin-brain. [documented; combination inferred]
6. Plain markdown + git as memory and spec store (Kiro 3 files, Cognition memory drive, Taskmaster tasks.json). Reviewable, diffable, tool-free. [documented]
7. Dependency validation on task graphs (Taskmaster validate/fix-dependencies); EARS-style testable acceptance criteria (Kiro) as the requirement -> test hook. [documented; chain to tests inferred]
8. Agentic search first; add an index or wiki only after a measured retrieval failure. Source: Claude Code team (vibes-level evidence, so the rule is cheap to revisit). [documented + inferred]
9. Retire scaffolding when a new model makes it unnecessary; re-ablate per model release. Source: Anthropic (Sonnet 4.5 -> Opus 4.5). [documented]

## Traps to avoid

1. Auto-generated context files / wikis presented as truth (ETH study; DeepWiki hallucination reports; staleness).
2. Full rewrites of the rules/memory file (ACE context collapse); unbounded growth (Auto Dream cap suggests the problem is real).
3. Unvetted self-learning: lessons from successful-looking trajectories get entrenched (OEP, 2605.29463). Require provenance and review.
4. Heavy persona/phase pipelines for small changes (BMAD, Spec Kit gates, 3-agent harness at about 20x cost). Reviewers report review overload.
5. Trusting vendor numbers (Bugbot comparisons, OpenAI 1/10 time, Superpowers token claims) and single-run, small-n evals (2607.22585 noise).
6. Assuming a cheaper model is cheaper per task (Databricks) or that a harness helps weak models more (unproven).
7. Counting token-count as cost: caching changes the economics (noted in Superpowers write-up). Measure dollars.
